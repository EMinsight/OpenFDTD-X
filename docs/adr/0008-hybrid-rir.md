# ADR-0008: 低域 FDTD + 高域 幾何音響 のハイブリッド RIR 合成

## Status

Accepted (2026-08-06) — 合成側 (`src/acoustics/core/HybridRir`、
AcousticSolverTab の合成パネル) と、2 ソルバーを順に起動する
「▶▶ ハイブリッド実行」まで実装済み。高域を出す幾何音響ソルバーは
OpenAcoustics の `ofdx_acoustic_ga` として実装された (2026-08-06)。

## Context

- 音響 FDTD の有効帯域は格子分解能で決まる。OpenAcoustics は
  `fmax = c/(10·dx)` (10 セル/波長で位相速度誤差 ~1%) を設計値として
  採用しており、RIR の `fs = ceil(c·√3/(0.99·dx))` は CFL 条件で
  決まるだけなので **fs/2 (ナイキスト) は有効帯域ではない**
  (fmax ≈ fs/17.5)。
- 実測: 7,200 m³ のホールを dx = 0.5 m で解くと fs = 1201 Hz・
  **fmax = 68.6 Hz**。歌声の可聴化に要る 4 kHz を FDTD 単独で得るには
  dx = 8.6 mm = 114 億セル (計算量は現状比 1.16e7 倍) となり、
  原理的に不可能。ソルバーの上限 (3,000 万セル) でも 553 Hz が限界。
- したがって広帯域の可聴化には「低域 = 波動論 (FDTD)、高域 = 幾何音響」の
  ハイブリッドが要る (実務の定石)。本 ADR は**合成の規約**を決める。
- FDTD の出力にはそのままでは足せない 3 つの事情がある:
  1. 出力は Green 関数 h ではなく **音源パルス s との畳み込み p = h*s**
     (s = ガウシアン微分、DC 成分 0、ピークは fmax/4)。
  2. s は遅延 **t0 = 5σ** を含む (dx = 0.5 m で 46 ms)。ソルバーの
     `anechoic` 検証も期待値を `t = t0 + r/c` としており補正されていない。
  3. 振幅規約が音源注入の仕方に依存する (幾何音響側は自由音場 1/(4πr))。

## Decision

### 1. 責務の分割

合成 (帯域分割して足す) は **GUI 側の音響コア**が担う。幾何音響ソルバーは
ADR-0007 の契約 (自分の作業ディレクトリへ `rir.wav` + `metadata.json`) を
そのまま満たす別バイナリとし、契約は変更しない。こうすると

- GUI は既存の `AcousticRunner` で両ソルバーを起動できる
- 合成器は「RIR ファイル 2 本」だけに依存し、ソルバーの完成を待たずに
  実装・検証できる

### 2. 前処理 — 音源パルスの逆フィルタ (t0 の除去を兼ねる)

`metadata.json` の `source.sigma_s` / `t0_s` から音源パルスを**同じ時間格子で
再構成**し、正則化つき逆フィルタ `H = P·conj(S)/(|S|² + ε·max|S|²)` を掛ける。
s が t0 を含むので、**この 1 手で遅延の除去も同時に済む** (直接音が r/c に来る)。
既定 ε = 1e-6 は増幅の上限が 1/(2√ε) = 500 倍 (54 dB) — 音源スペクトルが
fmax で −53 dB なので過不足がない。`sigma_s` が無い RIR (実測など) では
逆フィルタを行わず、**その旨を warning に出す** (黙って進めない)。

### 3. クロスオーバー — 線形位相の相補対

`h_hp = δ[center] − h_lp` (h_lp は Kaiser 窓 sinc、DC 利得を厳密に 1 に
正規化) を使う。**厳密に相補**なので、

- LP + HP = 単位インパルスの遅延 → 合成でエネルギーの山谷を作らない
  (selftest: 同一信号を両ブランチへ入れると出力が入力に一致、誤差 2e-16)
- 両ブランチの群遅延が同一 → 共通遅延 center を落とせば**時間原点が動かない**
  (直接音の到達時刻・ITDG が保たれる = 音響指標を壊さない)

クロスオーバーの既定値は `source.fmax_hz` (FDTD の有効帯域上限)。
FDTD のナイキスト以上は誤りなのでエラーにする。

### 3b. クロスオーバーの自動値は「両ソルバーの申告帯域の重なりの幾何平均」

FDTD は `source.fmax_hz` (上限)、幾何音響は `valid_band_hz[0]`
(= Schroeder 周波数 2000√(T60/V)、下限) を metadata.json で申告する。
重なり区間 [f_lo_GA, fmax_FDTD] の**幾何平均**を既定のクロスオーバーにする —
対数周波数で両方の限界から最も遠い点だから。片方しか分からないときは
FDTD の fmax を使う (従来どおり)。重なりが無い (f_lo_GA > fmax_FDTD)
ときも合成はするが、「その帯域はどちらの手法も担保しない」ことを
warning に出す (黙って埋めない)。

### 4. レベル整合は「クロスオーバー帯のバンドエネルギー」で行う

幾何音響側の振幅規約 (自由音場 1/(4πr)) を基準とし、**FDTD 側**に
ゲインを掛けて overlap 帯のエネルギーを合わせる。掛けた量 [dB] は必ず
UI に表示する (黙って正規化しない — 絶対規則 6 と同じ方針)。

### 5. 有効帯域の表示はナイキストではなく申告値を使う

可聴化の帯域警告は `metadata.json` の `source.fmax_hz` を優先し、
無い場合 (実測 RIR など) だけ fs/2 で代用する。ナイキストで代用すると
FDTD の帯域を**桁で過大に**表示してしまうため。

### 6. 2 ソルバーの起動は段ごとに作業ディレクトリを分ける

FDTD と幾何音響は ADR-0007 の同じ契約 (同じファイル名) で出力するので、
ハイブリッド実行では `hybrid_fdtd/` と `hybrid_ga/` に分けて走らせる。
中間の RIR は可聴化へ流さず、**最終的に設定するのは合成結果だけ**にする。
バックエンドを区別しない上書き設定 (`$OFDX_ACOUSTIC_SOLVER` など) は、
ファイル名がそのバックエンドの候補と一致するときだけ採用する
(`AcousticRunner::resolveSolverForHybrid`) — さもないと 2 本とも同じ
バイナリを起動してしまう。

## Consequences

- 合成器は幾何音響ソルバーの完成を待たずに実装・検証できた
  (selftest 47 checks + ヘッドレス実操作 21 checks)。
- 高域 RIR は `ofdx_acoustic_ga` が出す。バイナリは GUI に同梱しないので、
  UI は解決できないときにボタンを無効化して理由 (置き場所と名前) を
  ツールチップに出す (絶対規則 5)。
- 合成パネルの入力パスは**セッション限り**とし `.ofdx` へ保存しない
  (シリアライズ出力を 1 バイトも変えない — 絶対規則 2)。永続化が要る
  段階になったら追加キーとして足す。
- 逆フィルタの絶対振幅は保存されない (規約上の任意性がある) ため、
  合成後の RIR で**絶対 SPL を主張してはならない**。相対量 (T30, C80,
  可聴化) にのみ使う。
