# ADR-0009: 水中音響の海底地形 (.bty) と TL 断面

- 状態: 採用 (実装済み)
- 日付: 2026-08-06
- 関係: `src/io/BellhopIO`, `src/io/BathymetryIO`, `src/io/ShdReader`,
  `src/tabs/OceanEnvironmentTab`, `src/tabs/UnderwaterTab`, `src/kernel/Runner`

## 背景 (何が壊れていたか)

「海底地形マッピング」の設定をしてから「計算」を実行しても、bellhopcxx は
`=== normal end ===` を返すのに地形が結果に一切現れなかった。原因は 4 つで、
いずれも **エラーにならずに黙って無視される** 種類のものだった。

1. `BellhopIO` が `.bty` (BTYFIL) を書いていなかった。海底は SSP 最深点の
   平坦面。地形断面の表示自体も海域代表水深からの合成式で、実データでは
   なかった。
2. 底面オプションが `'A'` だった。BELLHOP が地形ファイルを読むのは
   **2 文字目が `~` または `*`** のときだけで
   (bellhopcuda `src/module/boundary.hpp` の `IsFile()`)、`.bty` を置いても
   `'A'` のままでは読まれない。
3. 「計算モード」「レイ数」「角度範囲」「ビーム種別」が UI だけの状態で、
   `.env` に一切渡っていなかった (RunType は常に `'C'`、NBEAMS 0、±45° 固定)。
   設定を変えても計算内容が変わらない。
4. 結果 (`.shd`) を読む手段が無く、実行後に出るのはファイルサイズの 1 行だけ。

## 決定

### 地形は「出所つきの断面」としてモデルに持つ

`UnderwaterOpts` に `bathymetry` (距離[km]×水深[m]) と `bathySource` を持つ。
断面は次のいずれかで、**どれなのかを必ず画面に出す**:

- ローカルデータセットからの実データ (出所 = ファイル名)
- 海域代表水深からの合成断面 (出所 = `synthetic`。図中に「合成断面
  (実データではない)」と明示する)

`.ofdx` へは追加キーとしてのみ書き、既定のままならキー自体を書かない
(旧ファイルとバイト一致)。

### 経路は測点 + 方位の大圏

`OceanEnvironmentTab` の緯度・経度・伝搬方位・距離から球面上の大圏を辿り、
水深グリッドを双線形補間してサンプリングする。**欠測 (陸域・NoData) を
含む格子では補間しない** — 海岸線を勝手に埋めると存在しない海域を計算に
渡すことになるため、その点は断面から落とす。経路の大半が陸なら
そのデータセットは採用せず次の候補へ回す。

### データセットは外部ライブラリ無しで読む

| 形式 | 用途 |
|---|---|
| Esri ASCII Grid (`.asc` / `.grd`) | GEBCO / ETOPO の領域指定ダウンロード |
| XYZ / CSV (`lon lat 標高`) | 同上のテキスト書出し |
| netCDF-4 (`.nc`) | GEBCO_2024 / ETOPO — **netCDF-4 は HDF5** なので、
  既にオプションで入っている HDF5 で読む (`USE_HDF5=ON` のときのみ) |
| BELLHOP `.bty` | 既にある地形断面をそのまま取り込む |

全球グリッドは数 GB あるので **必要な緯度経度の窓だけをハイパースラブで
読む** (`H5Reader::read2DWindow` / `read1DWindow` を追加)。座標軸 (1 次元)
だけは全部読んでよい (15 秒グリッドでも数百 KB)。

符号の規約は **内部では水深を正**。GEBCO/ETOPO は海面下が負の標高なので
読み込み時に反転し、水深 ≤ 0 (陸) は欠測として扱う。

### SSP は地形の最深点まで延長する

BELLHOP は「地形が SSP より深い」を実行時エラーにする
(`Bathymetry drops below the sound speed profile`)。`.env` を書くときに
断面の最深点まで末尾の音速で SSP を延長し、`DEPTH of bottom` もそこに合わせる。

### 実行設定は `.ofdx` 経由で `.env` へ

RunType は 2 文字 (計算モード + ビーム種別) を明示的に書く。**既定値は
従来と同じ挙動** — `'CG'` (コヒーレント TL + 幾何 hat ビーム, 直交座標) は、
1 文字だけ書いていた頃に bellhopcxx が既定で入れていた値
(`src/module/runtype.hpp` の `Validate()`) と同じ。UI の既定値も
これに合わせて変えた (旧 UI 既定はガウシアン/固有線で、モデルと食い違って
いた)。

### 結果は TL 断面として画面に出す

`ShdReader` が SHDFIL を読む。レコード長は先頭 int32 (4 byte 語数)、
音場は `rec 10 + irz` に complex float32 × NRr。受波器座標 (rec 8/9) は
**読まない** — 実数型が `BHC_USE_FLOATS` で float/double に変わるため、
`.env` を書いた GUI 側の等間隔値を使う。`TL = -20 log10|p|`、到達なし
(|p| = 0) は等高線に含めない。

## 検証

- `bellhopcxx` 実バイナリで、同一条件の平坦海底と傾斜海底 (200 m 棚 →
  2000 m) を比較: 有効点 9869 のうち **8865 点で |ΔTL| > 1 dB**。
  地形が黙殺されていないことを数値で確認した。
- GUI 通し: データセット配置 → 照会 → 実データ断面 101 点
  (1600 → 3137 m / 100 km) → 適用 → `.env` + `.bty` → 実行 →
  TL 断面 201×501 (45.6〜207.6 dB) の表示まで。
- `ofdx_selftest`: 7409 checks / 0 failures (追加 30)。`ctest` 16/16。

## 残っている制限 (UI にも明記する)

- 3 次元地形 (Nx2D / 3D の `.bty`) は未対応。断面 1 本の 2D のみ。
- 海面 (`.ati`) は未出力。波高の設定は計算に渡っていない。
- 底質の空間変化 (地形に沿った底質分布) は未対応 — 全域一様。
- 水中ドメインの FDTD / PE / ハイブリッドはカーネルが無く、ソルバー選択は
  常に bellhopcxx になる (タブに「未実装」と表示)。
