### 計算ボタンと ADR-0004 の整合 (2026-08-05)

音響ドメインの 計算 ボタンは ofd (電磁 FDTD) を波動アナロジーとして起動する
だけで音響指標の定量値は得られない (ADR-0004 — 音響 FDTD は外部専用ソルバー)。
定量計算と誤解させないため (絶対規則 5)、以下を追加:

- 計算実行前の確認ダイアログ (`MainWindow::runSimulation`、音響ドメインのみ。
  定量的な代替 3 経路 — 統計推定 / 実測 RIR 分析 / 外部音響ソルバー — へ誘導。
  「今後表示しない」は QSettings `run/acousticAnalogyWarned` に永続化)。
- 結果プロットの収束モード (⟨p⟩/⟨v⟩ 表示) に「波動アナロジー — 定量的な
  音響量ではありません」の注記 (`ppb_conv_ac_note`)、④音源の波形セクションに
  「励振は解析用波形で、音源リストの WAV は可聴化タブで RIR と畳み込む」の
  注記 (`sox_ac_wave_note`)、音響ソルバ連携タブに「ExternalFDTD ≠ OpenFDTD
  (ofd)」の明記とソルバー未検出時の具体的な導入案内。
- ofd の HDF5 `/metadata/VPoint` 波形からの RIR 抽出は**実装しない**:
  Maxwell の解 (ベクトル場・電磁境界/材料モデル) であり音響 RIR として
  書き出すと数値の捏造になるため (ADR-0004 の採択理由そのまま)。
- selftest +6 checks (確認ダイアログの I18n キーと文言の要点) で
  7158 → 7164。

### 音源の信号 (WAV) 設定と可聴化への受け渡し (2026-08-05)

「スピーカーから流れる音が設定できない」への対応。音源リストの「信号」列は
`.ofdx` `acoustic.sources[].signal` に保存されていたが、素の編集セルのみで
ファイル選択の導線が無かった。

- `AcousticSourceTab` に「🎵 信号 (WAV) を選択…」「信号を解除」ボタンを追加
  (選択行に対して動作。行未選択のときは無効化ではなく理由をダイアログで
  提示する)。信号列は従来どおり直接編集も可能 (自由記述の "chirp 3-5kHz"
  などを壊さない)。
- 表示は列幅の都合でファイル名のみ + ツールチップにフルパス。**実在しない
  パスはグレー表示 + 「ファイルが見つかりません」**をツールチップに出す
  (設定済みのように見せない — 絶対規則 5)。パス区切りか音声拡張子を持つ
  文字列だけをファイルとみなし、自由記述はそのまま表示する。
- `AuralizationTab` の①入力に「🎵 音源リストから」を追加。信号が設定された
  **有効な**音源から 1 つ選んで `auralizationDryFile` に入れる。候補が無い
  ときはボタンを無効化し、理由 (音源/WAV/指向性タブで信号を設定する) を
  ツールチップに出す。**複数音源の同時再生 (ミックス) は未実装**であることを
  UI に明記し、合成が要る場合は音響編集・解析タブで作った WAV を選ぶよう案内。
- 反映ロジックは `AuralizationTab::drySourceCandidates` /
  `setDryFromSource` (ヘッダ内 inline static) に切り出し、selftest +13 checks
  (候補の選別・取り込み・範囲外/無効行/信号なしの拒否とモデル不変・
  フルパスの `.ofdx` ラウンドトリップ) で検証。7164 → 7177。

### 音響ソルバ実行結果の RIR を実測RIR分析タブへ反映 (2026-08-05)

`AcousticSolverTab` は `rirReady` で `operaAcoustic().rirPath` を書いて
`touch()` していたが、`RirAnalysisTab` は `Project::loaded` にしか
`refresh` を繋いでいないため、実行後にタブを開いても WAV 欄が空のままだった
(バグ)。`AcousticSolverTab::rirAssigned(QString)` を追加し、`MainWindow` が
`RirAnalysisTab::applySolverRir` へ中継する (タブ同士の直接依存を作らない)。
`Project::changed` への無差別接続は編集中の入力欄を他タブの `touch()` で
上書きし得るため採らず、「実行完了」という単発イベントだけを橋渡しする。
反映されたことが分かるよう、WAV 欄の直下に「音響ソルバ連携の実行結果 (%1) を
実測RIRに設定しました — 下の『▶ RIR を分析』で分析できます」のヒントを出す
(利用者が別ファイルを選び直したら消える)。

### ハイブリッド RIR 合成 (低域 FDTD + 高域 幾何音響) — 合成側 (2026-08-06)

FDTD の有効帯域は格子分解能で決まる (`fmax = c/(10·dx)`。dx = 0.5 m の
実例で **68.6 Hz** — RIR の fs 1201 Hz のナイキスト 601 Hz ではない)。
歌声の可聴化に要る 4 kHz は FDTD 単独では 114 億セルとなり原理的に
不可能なので、低域を FDTD・高域を幾何音響が担う合成を実装した。
設計判断は **ADR-0008**。**幾何音響ソルバー自体は未実装** (OpenAcoustics 側の
別課題) で、ここは「足す」側だけ。

- `src/acoustics/core/HybridRir` (C++14, Qt 非依存):
  - **音源パルスの逆フィルタ** — FDTD の出力は Green 関数ではなく
    「ガウシアン微分パルス s との畳み込み」。metadata の σ / t0 から s を
    再構成し正則化逆フィルタ (ε 既定 1e-6 = 増幅上限 54 dB) を掛ける。
    s が t0 を含むので**遅延の除去も同時に済む** (直接音が r/c に来る)。
  - **相補な線形位相クロスオーバー** — `h_hp = δ[center] − h_lp`。厳密に
    相補なので合成でエネルギーの山谷ができず、共通遅延を落とせば
    時間原点 (直接音・ITDG) が保たれる。
  - **レベル整合** — クロスオーバー帯のバンドエネルギーで FDTD 側を
    幾何音響側 (自由音場 1/(4πr) 規約) に合わせ、掛けた量を UI に出す。
- `QtAcousticAdapter::readSolverMetadata` / `metadataForRir` を新設し、
  ADR-0007 の `metadata.json` から `source.fmax_hz` / `sigma_s` / `t0_s` /
  `grid.dx_m` を読む。可聴化の**帯域警告もこの申告値を使う**ように変更
  (従来は fs/2 = ナイキストで、FDTD の帯域を桁で過大表示していた)。
- AcousticSolverTab に合成パネルを追加 (低域/高域/出力 RIR、クロスオーバー
  = 空欄で自動、▶ 合成する、合成結果を可聴化の RIR に設定)。幾何音響 RIR が
  未指定なら**ボタンを無効化して理由をツールチップに**出す (絶対規則 5)。
  入力パスは**セッション限り** — `.ofdx` は 1 バイトも変えない (絶対規則 2)。
- 検証: selftest +47 checks (相補性の再構成誤差 2e-16 / 時間原点 / 帯域の
  出所と入れ替え時の 80 dB 以上の阻止 / 逆フィルタによる t0 除去と反射比の
  復元 / レベル整合 +6.02 dB / 自動クロスオーバー / 異常系 / metadata の
  往復と契約外 JSON の拒否)、ヘッドレス実操作 21 checks

### 端数 fs の RIR を可聴化できるようにした (2026-08-06)

実測の不具合報告への対応。ホール解析の RIR (FDTD ソルバー出力、
格子刻みから決まる **fs = 1201 Hz**) と 48 kHz のドライ歌唱を可聴化すると
`UnsupportedSampleRate — rir resample: conversion ratio 48000/1201 exceeds
the supported factor limit (4096)` で失敗していた。

- **原因**: リサンプラは約分後の L/M をそのまま 1 段のポリフェーズで
  実装しており、L が 1 段の上限 (4096) を超える比を扱えなかった。
  標準 fs 同士 (最大 640 = 11025↔48000) しか想定していなかったが、
  FDTD の RIR は fs が格子刻みで決まるため端数 (素数を含む) になる。
- **対応 (`src/acoustics/core/Resampler.cpp`)**: L と M を上限以下の因子へ
  分けた**多段カスケード**を実装。中間レートが
  min(fs_in, fs_out) 〜 max(fs_in, fs_out) に収まる分割だけを採用するので
  (`ratesStayInRange`)、通過帯域端 (0.90 × min ナイキスト) と阻止域
  (~90 dB/段) は 1 段の場合と同じ。1201→48000 は 2 段 (3000/1201 → 16/1)
  で、タップ数は 1 段換算 549 万 → **34.5 万**に収まる。
  分割できない比 (fs が大きな素数) は max(L,M) ≤ 65536 なら 1 段で押し切り、
  それも超える比だけをエラーにする (黙って劣化させない)。
  **1 段で足りる比の経路・出力は従来と完全に同一** (標準 fs は無変更)。
- **帯域の明示**: fs を上げても RIR の帯域は広がらない (1201 Hz の RIR は
  601 Hz まで)。48 kHz の出力を「高域まである音」と誤解させないよう、
  RIR のナイキストが 16 kHz 未満なら警告を出す。文言は 3 タブ
  (可聴化 単発/一括・音響解析) で共有するため
  `tabhelp::rirSampleRateNotes` に集約した。変換不能時のメッセージにも
  実際の fs (変換元→変換先) が入るようにした。
- 検証: selftest +30 checks (多段の振幅 ±0.1 dB / イメージ ≤ −85 dB /
  群遅延 / 決定性 / 出力長 / 素数 fs のフォールバック / 上限超えの拒否と
  メッセージ / 標準 fs が 1 段のままであること / 注記の生成規則)。
  実データ相当のヘッドレス e2e 13 checks (48 kHz ドライ × 1201 Hz RIR →
  48 kHz ウェット WAV、注記 2 行)。7276 → 7306。

### 光導波路モードソルバ FDE (2026-08-04)

`src/optics/FdeModeSolver` (Qt 非依存 C++17) を新設し、モードソルバ FDE タブの
表示を簡易近似式から実計算へ置き換えた。手法は断面 2D の 5 点差分 + 虚軸伝搬
(シフト逆べき乗) + ADI/Thomas 三重対角解 + Gram-Schmidt デフレーション、
スカラー / 半ベクトル TE・TM 対応。出力は neff / |E|² 分布 / 閉込め係数 Γ /
実効断面積で、ng・群速度分散 D・複屈折 Δn・dneff/dT・dneff/dw・プロセスコーナーは
λ・寸法・温度を変えた複数ソルブの差分から実算出する。材料は
`src/optics/MaterialDispersion` (公刊 Sellmeier + 熱光学係数 dn/dT、出典明記) を
材料Explorer と共用する。

検証は対称 3 層スラブの厳密解 (超越方程式を selftest 側で二分法により独立に解く)
との比較で、dy = 10/5/2.5 nm の誤差比が 3 点とも 0.250 = **2 次収束**を確認
(離散化誤差でありスキームのバグでないことの証明)。実効屈折率法との交差検証、
モード直交性、決定性、Γ の範囲も検査 (計 76 checks)。
既定条件 (Si 450×220 nm / SiO₂ / 1550 nm / TE) で **0.6 秒**、実 GUI での
実測は計算 1.2 秒・掃引 4.3 秒・コーナー 3.6 秒。

**曲げ損失は対象外** (曲がり導波路の漏れモード = 複素 neff 解析が必要) で
固定サンプル + `sampleNote` を維持。伝搬損失 [dB/cm] も実屈折率のみの FDE では
求まらないため「—」表示。モード波源・モード展開モニター・Schematic への
受け渡しは受け側モデルが未実装のため `markNotImplemented` を維持。

### 薄膜多層膜タブの未配線解消 — 周期記法・膜厚最適化・レシピ・感度 (2026-08-07)

`ThinFilmTab` に残っていた 10 個の未実装マーカーのうち 6 個を実装で解消した

- 新規 `src/optics/FilmNotation` (Qt 非依存) — 多層膜の周期記法
  (Macleod 記法) のパーサ。`Air | (H L)^12 H | Sub  H=Si3N4 L=SiO2 @ 1550nm`
  を層列へ展開する。係数 (`0.5H` = 1/8 波長、`2L` = 半波長)、入れ子の

  (Nelder–Mead シンプレックス法, Computer Journal 7, 308 (1965))。層数・材料は
  固定で**物理膜厚だけ**を動かす。乱数を使わないので同じ入力からは常に同じ

- タブ側の配線: 「展開」(周期記法 → 層構成)、「最適化実行」(改善したときだけ

- 周期記法 → 物理膜厚 → 特性行列法の経路を、四分の一波長積層の閉形式

### 室内音響タブ: 帯域内 INR の検査 (ISO 3382-2) (2026-08-07)

  そのまま表にしたもの: EDT 20 dB / T20 35 dB / T30 45 dB
- `RirAnalyzer` が帯域信号のピークと末尾ノイズフロアの差を
  `BandMetricsResult::{noiseOk, peakDb, noiseFloorDb, inrDb}` へ入れる
  (ISO 18233:2006 §3.6 の INR)。**広帯域の `preprocess.dynamicRangeDb` とは
  別物**で、低域ほど厳しくなるため帯域ごとに見る必要がある
- タブ側はチェックで表に INR 行を足し、ISO の要求に照らして色分け
  (T30 可 / T20 まで / 不足) + 何 dB 足りないかをツールチップに出す。
  まとめ行に「T30 の 45 dB に足りない帯域」「T20 の 35 dB に足りない帯域」と
  最小 INR を出し、S/N を上げる手段 (音源出力・平均回数) を添える。
  統計推定にはノイズフロアが無いので、実測 IR を解析したときだけ出す

検証は新規 ctest `acoustics.inr` (65 checks)。芯は **INR の判定と指標の
`valid` が食い違わないこと** — INR が要求を下回る帯域で T30 が valid に
なったら画面の説明が嘘になる。ノイズフロア −70/−45/−28 dBFS × 6 帯域で確認。
数値は `docs/opera-acoustics-validation.md` §13 に記載。

- `convolveWithPrep` — 既定設定で従来の `convolveFiles` と**出力 WAV が
  バイト一致**すること (リファクタの回帰ガード)、ゲイン +6.02 dB が出力
  ピークを同量押し上げること、トリムが出力長を縮めること

### 室内音響タブ: ESS 逆畳み込みと高調波分離 (2026-08-08)

「ESS 逆畳み込み」「高調波分離」のチェックボックスが未実装のまま置かれて
いたのを実装した。実測の現場にあるのはインパルス応答ではなく **掃引を
再生した録音** なので、ここが無いと実測 IR を取り込む入口が塞がっている。

- 新規 `src/acoustics/core/SweepDeconvolution` (C++14, Qt 非依存) —
  ESS の生成 / 逆フィルタ / 逆畳み込み / 高調波分離 (Farina 2000)。
  逆フィルタは時間反転 + 6 dB/oct 補正で、**掃引そのものを逆畳み込みすると
  振幅 1 の単一インパルスになる**ようスカラー正規化してある
- `.ofdx` `opera_analysis.sweep` (追加キー、既定ならキー自体を書かない)
- `QtAcousticAdapter::analyzeFile` が `sweepDeconvolve` 有効時に録音を
  逆畳み込みしてから分析する。**逆畳み込みに失敗したら IR として解析し
  直したりしない** (掃引のつもりの録音を IR として解析すると意味のない
  指標が出るため、エラーにする)
- 画面には逆畳み込みした事実と **帯域制限** (掃引の範囲外は復元できない)、
  高調波分離時は THD と次数別レベルを必ず出す

検証は新規 ctest `acoustics.sweep` (47 checks)。芯は
**復元結果 == h ⊛ 帯域制限核** という線形時不変性で、実測の最大差は
**3.33e-16** (機械精度)。帯域制限でデルタが復元できないこと自体も
リンギング量として検証に固定した。数値は
`docs/opera-acoustics-validation.md` §14 に記載。

### H5 ビューア: 時間範囲の再生反映と動画設定の ffmpeg 配線 (2026-08-08)

H5 ビューアで「時間範囲の入力が再生に反映されない」「動画設定 (FPS/解像度/
コーデック) が ffmpeg 呼び出しに反映されない」という 2 つの `unwiredNote` を
解消した。どちらも「入力欄はあるが効かない」状態だった。

- 新規 `src/io/MovieExport` (純関数のみ) — `frameRangeForTimes()` と
  `buildFfmpegArgs()`。ffmpeg を起動せずに selftest から検証できるよう、
  GUI から切り離してある
- `H5Reader::readOfdSeriesTimes()` — `/timeseries/time` (H は `time_H`) から
  各フレームの時刻 [s] を読む。旧 `/data%06d` 形式には時刻が無いので
  **絞り込み自体を無効化して理由を出す** (フレーム番号を時刻とみなすような
  推測はしない)
- 時間範囲は再生と**書き出しの両方**に効く (画面で見ている範囲と書き出しが
  ずれない)。動画化するときだけ PNG を 0 始まりの連番に振り直す
  (ffmpeg の `%05d` が 0 始まりのため)。PNG 連番として出すときは元のフレーム
  番号を残す
- 動画設定は ffmpeg へ渡る。解像度「元のまま」を既定にして拡大でぼかさない。
  片側だけ指定したときは `-2` でアスペクト比を保つ。**scale は crop より前**
  (順序が逆だと yuv420p 用の偶数化が壊れる)
- 凡例・形状の焼き込みはレンダリング側の話で ffmpeg ではどうにもならないため、
  未実装として明示・無効化した

検証 (selftest +27 checks)。実装中に**境界の浮動小数点問題**を見つけて直した:
時刻列が `t[i] = i·Δt` と積まれていると `9·1e-9 > 9e-9` になり、利用者が
「フレームの時刻ちょうど」を境界に入れたときにそのフレームが外れる。
相対イプシロン 1e-9 (フレーム間隔よりはるかに小さく、丸め誤差よりはるかに
大きい) で比較するようにした。

### 形状タブ: メッシュの自動修復 (2026-08-08)

`GeometryTab`「ジオメトリ修復」の「▶ 自動修復実行」が未実装 (検出のみ) の
まま置かれていたのを実装した。検出側 (`io/MeshDiagnostics`) は既に実計算
だったので、対になる修復側を足した形。

- 新規 `src/io/MeshRepair` (Qt Widgets 非依存、決定的) — 3 つの修復:
  ① 頂点溶接 (位相を作る前提工程。常に行う)、② 縮退三角形の除去、
  ③ 法線の統一 (面の隣接グラフを幅優先で辿り、辺を共有する 2 枚が逆向きに
  辿るよう裏返す)。連結成分が**閉じている**場合は符号付き体積で外向きへ
  揃える (開いた成分は基準が無いので触らない)
- **穴埋めは実装していない**。塞ぎ方が一意でなく形状を変えるので、黙って
  埋めずに「境界エッジが N 本残っている」と報告して元の CAD での修正を促す
- タブは修復後に配置・変換をかけ直して検査をやり直し、何をどれだけ直したか
  (溶接・除去・反転の数、外向き化した成分数、残った穴) を必ず出す

検証は selftest +41 checks。既存の `orientedCube` 群を再利用して、構成した
欠陥から期待値が決まる形にした:

- 健全な立方体 → 溶接 28 頂点のみ、表面積 6a² と bbox が不変
- 1 枚裏返した立方体 → 不一致辺 3 本が **0** になり水密のまま、三角形は減らない
- 全面内向きの立方体 → 検出には引っかからない (向きは「一致」している) が、
  符号付き体積で外向きへ反転される。反転が符号を**厳密に**変えること
  (`vol6(fixed) == -vol6(inward)`) と、大きさが 6a³ = 4.8e-5 に一致することを確認
- 縮退三角形 → 除去され、`dropDegenerate = false` では残る
- 穴あき → 塞がず境界エッジ 3 本を報告、三角形は増えない
- 決定性と冪等性 (直したものを直しても幾何が変わらない)

浮動小数点まわりで 2 点、**テスト側の期待値が誤っていた**ので直した:
頂点が float なので 6V の比較は相対 1e-6 が要る (絶対 1e-12 では実測差
3.2e-12 で落ちる)。また `ImportedMesh` は常に三角形スープ (頂点を共有しない
形式) なので、修復後に再度溶接しても「消えた頂点 28」は変わらない — これは
正常なので、冪等性は幾何の一致で判定するようにした。

### 形状タブ: 主軸の自動検出 (2026-08-08)

「配置・変換」の「主軸を自動検出」チェックが未実装のまま置かれていたのを
実装した。傾いた STL を取り込んだときに、手で回転角を探さずに軸へ揃えられる。

- 新規 `src/io/MeshAxes` (Qt Widgets 非依存、決定的) — **面積重み付き**の
  慣性主軸。頂点をそのまま使う PCA は頂点密度に引きずられる (細かく切った
  面が重く効く) ので採らず、三角形ごとの閉形式 2 次モーメント
  `∫_T (p−g)(p−g)ᵀ dA = (A/12) Σ (p_i − g)(p_i − g)ᵀ` を平行軸の定理で
  積む。固有値分解は対称 3×3 の Jacobi 法 (乱数・時刻を使わない)
- 軸は固有値の降順、符号は「絶対値最大の成分を正」で一意化し右手系へ。
  配置・変換が X→Y→Z の順に回すので、その形から Euler 角を抽出する
- **主軸が縮退している形 (立方体・球のように回しても同じ) では回転を入れず
  理由を出す**。一意に決まらないのに角度を入れると「検出できた」と誤解させる

検証は selftest +27 checks。角度そのものではなく **戻した結果の形** で判定
する (主軸には符号・入れ替えの自由度があり、利用者にとっての正しさは
「軸に整列するか」なので):

- 軸に沿った直方体 → 第 1 主軸が最長辺の X、角度は 0、モーメントは狭義単調減少
- 既知の角度 (単軸 3 種 + 3 軸複合) で傾けた 2a×a×a/2 の直方体 → 検出した
  角度で戻すと bbox の辺長が元の (a/2, a, 2a) に一致する (相対 1e-5)
- 立方体は縮退として報告される
- 面積 0 に近い微小三角形を 200 個足しても第 1 主軸が変わらない
  (面積重み付けが効いていること — 頂点 PCA なら寄ってしまう)
- 決定性と不正入力

### 形状タブ: ボクセル化の内外判定 (一般化巻き数) と区間まとめの配線 (2026-08-08)

ボクセル化のオプション群が「入力欄はあるが Voxelizer が読まない」状態
だったのを、実装できるものだけ実際に効かせた。

- `Voxelizer::windingNumber()` — 一般化巻き数 (Jacobson et al., ACM TOG
  32(4), 2013)。各三角形が張る符号付き立体角の和 / 4π で、閉じた面の内側で
  1、外側で 0。立体角は Van Oosterom & Strackee (1983) の閉形式
  `tan(Ω/2) = a·(b×c) / (|a||b||c| + (a·b)|c| + (a·c)|b| + (b·c)|a|)` を
  `atan2` で評価する
- `VoxelOptions{ inside, mergeRuns }` を追加。内外判定 (レイの偶奇 / 巻き数)
  と「連続セルをまとめる」が実際に効く。**既定はレイの偶奇** — UI は
  巻き数が既定になっていて実装 (レイ) と食い違っていたので実装側へ揃えた
- **巻き数は法線の向きが揃っていることが前提**。揃っていないと + と − が
  打ち消し合い、内側でも w ≈ 0 になって全セルが「外」になる。GUI は
  `MeshDiagnostics::inconsistentEdges > 0` なら実行せず、PR #66 で入れた
  「ジオメトリ修復」(法線統一) へ誘導する
- 表面処理の共形・サブセル、PVF、八分木、GPU はエンジン未実装なので
  個別に markNotImplemented を付けて、何が効いて何が効かないかを明示した

検証は selftest +45 checks。**穴の開いたメッシュでの差が採用理由そのもの**:

| 手法 | 占有セル (真値 216) | 誤差 |
|---|---|---|
| レイの偶奇 | 126 | 90 |
| 一般化巻き数 | **216** | **0** |

閉じたメッシュでは両者一致 (216 セル / 36 直方体)。巻き数は内側で |w| = 1、
外側で 0 が 1e-9 で成り立つこと、箱の大きさに依らないことも確認した。
「まとめない」設定は占有セル数を変えずに 1 セル 1 直方体 (216 個、各 1 セル幅)
になることを検証している。

実装中に、テスト用の `boxMesh` が **向きの揃っていない三角形スープ** だった
ことが分かった (レイの偶奇は向きに依らないので今まで露見しなかった)。
外向きで首尾一貫するよう直した — 巻き数の検証にはこれが必須。
