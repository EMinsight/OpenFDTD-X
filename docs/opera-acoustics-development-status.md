### 計算ボタンと ADR-0004 の整合 (2026-08-05)

音響ドメインの 計算 ボタンは ofd (電磁 FDTD) を波動アナロジーとして起動する
だけで音響指標の定量値は得られない (ADR-0004 — 音響 FDTD は外部専用ソルバー)。
定量計算と誤解させないため (絶対規則 5)、以下を追加:

- 計算実行前の確認ダイアログ (`MainWindow::runSimulation`、音響ドメインのみ。
  定量的な代替 3 経路 — 統計推定 / 実測 RIR 分析 / 外部音響ソルバー — へ誘導。
  「今後表示しない」は QSettings `run/acousticAnalogyWarned` に永続化)。
- 結果プロットの収束モード (⟨p⟩/⟨v⟩ 表示) に「波動アナロジー — 定量的な
  音響量ではありません」の注記 (`ppb_conv_ac_note`)、④音源の波形セクションに
  「励振は解析用波形で、音源リストの WAV は可聴化タブで RIR と畳み込む」の
  注記 (`sox_ac_wave_note`)、音響ソルバ連携タブに「ExternalFDTD ≠ OpenFDTD
  (ofd)」の明記とソルバー未検出時の具体的な導入案内。
- ofd の HDF5 `/metadata/VPoint` 波形からの RIR 抽出は**実装しない**:
  Maxwell の解 (ベクトル場・電磁境界/材料モデル) であり音響 RIR として
  書き出すと数値の捏造になるため (ADR-0004 の採択理由そのまま)。
- selftest +6 checks (確認ダイアログの I18n キーと文言の要点) で
  7158 → 7164。

### 音源の信号 (WAV) 設定と可聴化への受け渡し (2026-08-05)

「スピーカーから流れる音が設定できない」への対応。音源リストの「信号」列は
`.ofdx` `acoustic.sources[].signal` に保存されていたが、素の編集セルのみで
ファイル選択の導線が無かった。

- `AcousticSourceTab` に「🎵 信号 (WAV) を選択…」「信号を解除」ボタンを追加
  (選択行に対して動作。行未選択のときは無効化ではなく理由をダイアログで
  提示する)。信号列は従来どおり直接編集も可能 (自由記述の "chirp 3-5kHz"
  などを壊さない)。
- 表示は列幅の都合でファイル名のみ + ツールチップにフルパス。**実在しない
  パスはグレー表示 + 「ファイルが見つかりません」**をツールチップに出す
  (設定済みのように見せない — 絶対規則 5)。パス区切りか音声拡張子を持つ
  文字列だけをファイルとみなし、自由記述はそのまま表示する。
- `AuralizationTab` の①入力に「🎵 音源リストから」を追加。信号が設定された
  **有効な**音源から 1 つ選んで `auralizationDryFile` に入れる。候補が無い
  ときはボタンを無効化し、理由 (音源/WAV/指向性タブで信号を設定する) を
  ツールチップに出す。**複数音源の同時再生 (ミックス) は未実装**であることを
  UI に明記し、合成が要る場合は音響編集・解析タブで作った WAV を選ぶよう案内。
- 反映ロジックは `AuralizationTab::drySourceCandidates` /
  `setDryFromSource` (ヘッダ内 inline static) に切り出し、selftest +13 checks
  (候補の選別・取り込み・範囲外/無効行/信号なしの拒否とモデル不変・
  フルパスの `.ofdx` ラウンドトリップ) で検証。7164 → 7177。

### 音響ソルバ実行結果の RIR を実測RIR分析タブへ反映 (2026-08-05)

`AcousticSolverTab` は `rirReady` で `operaAcoustic().rirPath` を書いて
`touch()` していたが、`RirAnalysisTab` は `Project::loaded` にしか
`refresh` を繋いでいないため、実行後にタブを開いても WAV 欄が空のままだった
(バグ)。`AcousticSolverTab::rirAssigned(QString)` を追加し、`MainWindow` が
`RirAnalysisTab::applySolverRir` へ中継する (タブ同士の直接依存を作らない)。
`Project::changed` への無差別接続は編集中の入力欄を他タブの `touch()` で
上書きし得るため採らず、「実行完了」という単発イベントだけを橋渡しする。
反映されたことが分かるよう、WAV 欄の直下に「音響ソルバ連携の実行結果 (%1) を
実測RIRに設定しました — 下の『▶ RIR を分析』で分析できます」のヒントを出す
(利用者が別ファイルを選び直したら消える)。

### ハイブリッド RIR 合成 (低域 FDTD + 高域 幾何音響) — 合成側 (2026-08-06)

FDTD の有効帯域は格子分解能で決まる (`fmax = c/(10·dx)`。dx = 0.5 m の
実例で **68.6 Hz** — RIR の fs 1201 Hz のナイキスト 601 Hz ではない)。
歌声の可聴化に要る 4 kHz は FDTD 単独では 114 億セルとなり原理的に
不可能なので、低域を FDTD・高域を幾何音響が担う合成を実装した。
設計判断は **ADR-0008**。**幾何音響ソルバー自体は未実装** (OpenAcoustics 側の
別課題) で、ここは「足す」側だけ。

- `src/acoustics/core/HybridRir` (C++14, Qt 非依存):
  - **音源パルスの逆フィルタ** — FDTD の出力は Green 関数ではなく
    「ガウシアン微分パルス s との畳み込み」。metadata の σ / t0 から s を
    再構成し正則化逆フィルタ (ε 既定 1e-6 = 増幅上限 54 dB) を掛ける。
    s が t0 を含むので**遅延の除去も同時に済む** (直接音が r/c に来る)。
  - **相補な線形位相クロスオーバー** — `h_hp = δ[center] − h_lp`。厳密に
    相補なので合成でエネルギーの山谷ができず、共通遅延を落とせば
    時間原点 (直接音・ITDG) が保たれる。
  - **レベル整合** — クロスオーバー帯のバンドエネルギーで FDTD 側を
    幾何音響側 (自由音場 1/(4πr) 規約) に合わせ、掛けた量を UI に出す。
- `QtAcousticAdapter::readSolverMetadata` / `metadataForRir` を新設し、
  ADR-0007 の `metadata.json` から `source.fmax_hz` / `sigma_s` / `t0_s` /
  `grid.dx_m` を読む。可聴化の**帯域警告もこの申告値を使う**ように変更
  (従来は fs/2 = ナイキストで、FDTD の帯域を桁で過大表示していた)。
- AcousticSolverTab に合成パネルを追加 (低域/高域/出力 RIR、クロスオーバー
  = 空欄で自動、▶ 合成する、合成結果を可聴化の RIR に設定)。幾何音響 RIR が
  未指定なら**ボタンを無効化して理由をツールチップに**出す (絶対規則 5)。
  入力パスは**セッション限り** — `.ofdx` は 1 バイトも変えない (絶対規則 2)。
- 検証: selftest +47 checks (相補性の再構成誤差 2e-16 / 時間原点 / 帯域の
  出所と入れ替え時の 80 dB 以上の阻止 / 逆フィルタによる t0 除去と反射比の
  復元 / レベル整合 +6.02 dB / 自動クロスオーバー / 異常系 / metadata の
  往復と契約外 JSON の拒否)、ヘッドレス実操作 21 checks

### 端数 fs の RIR を可聴化できるようにした (2026-08-06)

実測の不具合報告への対応。ホール解析の RIR (FDTD ソルバー出力、
格子刻みから決まる **fs = 1201 Hz**) と 48 kHz のドライ歌唱を可聴化すると
`UnsupportedSampleRate — rir resample: conversion ratio 48000/1201 exceeds
the supported factor limit (4096)` で失敗していた。

- **原因**: リサンプラは約分後の L/M をそのまま 1 段のポリフェーズで
  実装しており、L が 1 段の上限 (4096) を超える比を扱えなかった。
  標準 fs 同士 (最大 640 = 11025↔48000) しか想定していなかったが、
  FDTD の RIR は fs が格子刻みで決まるため端数 (素数を含む) になる。
- **対応 (`src/acoustics/core/Resampler.cpp`)**: L と M を上限以下の因子へ
  分けた**多段カスケード**を実装。中間レートが
  min(fs_in, fs_out) 〜 max(fs_in, fs_out) に収まる分割だけを採用するので
  (`ratesStayInRange`)、通過帯域端 (0.90 × min ナイキスト) と阻止域
  (~90 dB/段) は 1 段の場合と同じ。1201→48000 は 2 段 (3000/1201 → 16/1)
  で、タップ数は 1 段換算 549 万 → **34.5 万**に収まる。
  分割できない比 (fs が大きな素数) は max(L,M) ≤ 65536 なら 1 段で押し切り、
  それも超える比だけをエラーにする (黙って劣化させない)。
  **1 段で足りる比の経路・出力は従来と完全に同一** (標準 fs は無変更)。
- **帯域の明示**: fs を上げても RIR の帯域は広がらない (1201 Hz の RIR は
  601 Hz まで)。48 kHz の出力を「高域まである音」と誤解させないよう、
  RIR のナイキストが 16 kHz 未満なら警告を出す。文言は 3 タブ
  (可聴化 単発/一括・音響解析) で共有するため
  `tabhelp::rirSampleRateNotes` に集約した。変換不能時のメッセージにも
  実際の fs (変換元→変換先) が入るようにした。
- 検証: selftest +30 checks (多段の振幅 ±0.1 dB / イメージ ≤ −85 dB /
  群遅延 / 決定性 / 出力長 / 素数 fs のフォールバック / 上限超えの拒否と
  メッセージ / 標準 fs が 1 段のままであること / 注記の生成規則)。
  実データ相当のヘッドレス e2e 13 checks (48 kHz ドライ × 1201 Hz RIR →
  48 kHz ウェット WAV、注記 2 行)。7276 → 7306。

### 光導波路モードソルバ FDE (2026-08-04)

`src/optics/FdeModeSolver` (Qt 非依存 C++17) を新設し、モードソルバ FDE タブの
表示を簡易近似式から実計算へ置き換えた。手法は断面 2D の 5 点差分 + 虚軸伝搬
(シフト逆べき乗) + ADI/Thomas 三重対角解 + Gram-Schmidt デフレーション、
スカラー / 半ベクトル TE・TM 対応。出力は neff / |E|² 分布 / 閉込め係数 Γ /
実効断面積で、ng・群速度分散 D・複屈折 Δn・dneff/dT・dneff/dw・プロセスコーナーは
λ・寸法・温度を変えた複数ソルブの差分から実算出する。材料は
`src/optics/MaterialDispersion` (公刊 Sellmeier + 熱光学係数 dn/dT、出典明記) を
材料Explorer と共用する。

検証は対称 3 層スラブの厳密解 (超越方程式を selftest 側で二分法により独立に解く)
との比較で、dy = 10/5/2.5 nm の誤差比が 3 点とも 0.250 = **2 次収束**を確認
(離散化誤差でありスキームのバグでないことの証明)。実効屈折率法との交差検証、
モード直交性、決定性、Γ の範囲も検査 (計 76 checks)。
既定条件 (Si 450×220 nm / SiO₂ / 1550 nm / TE) で **0.6 秒**、実 GUI での
実測は計算 1.2 秒・掃引 4.3 秒・コーナー 3.6 秒。

**曲げ損失は対象外** (曲がり導波路の漏れモード = 複素 neff 解析が必要) で
固定サンプル + `sampleNote` を維持。伝搬損失 [dB/cm] も実屈折率のみの FDE では
求まらないため「—」表示。モード波源・モード展開モニター・Schematic への
受け渡しは受け側モデルが未実装のため `markNotImplemented` を維持。

### 薄膜多層膜タブの未配線解消 — 周期記法・膜厚最適化・レシピ・感度 (2026-08-07)

`ThinFilmTab` に残っていた 10 個の未実装マーカーのうち 6 個を実装で解消した

- 新規 `src/optics/FilmNotation` (Qt 非依存) — 多層膜の周期記法
  (Macleod 記法) のパーサ。`Air | (H L)^12 H | Sub  H=Si3N4 L=SiO2 @ 1550nm`
  を層列へ展開する。係数 (`0.5H` = 1/8 波長、`2L` = 半波長)、入れ子の

  (Nelder–Mead シンプレックス法, Computer Journal 7, 308 (1965))。層数・材料は
  固定で**物理膜厚だけ**を動かす。乱数を使わないので同じ入力からは常に同じ

- タブ側の配線: 「展開」(周期記法 → 層構成)、「最適化実行」(改善したときだけ

- 周期記法 → 物理膜厚 → 特性行列法の経路を、四分の一波長積層の閉形式

### 室内音響タブ: 帯域内 INR の検査 (ISO 3382-2) (2026-08-07)

  そのまま表にしたもの: EDT 20 dB / T20 35 dB / T30 45 dB
- `RirAnalyzer` が帯域信号のピークと末尾ノイズフロアの差を
  `BandMetricsResult::{noiseOk, peakDb, noiseFloorDb, inrDb}` へ入れる
  (ISO 18233:2006 §3.6 の INR)。**広帯域の `preprocess.dynamicRangeDb` とは
  別物**で、低域ほど厳しくなるため帯域ごとに見る必要がある
- タブ側はチェックで表に INR 行を足し、ISO の要求に照らして色分け
  (T30 可 / T20 まで / 不足) + 何 dB 足りないかをツールチップに出す。
  まとめ行に「T30 の 45 dB に足りない帯域」「T20 の 35 dB に足りない帯域」と
  最小 INR を出し、S/N を上げる手段 (音源出力・平均回数) を添える。
  統計推定にはノイズフロアが無いので、実測 IR を解析したときだけ出す

検証は新規 ctest `acoustics.inr` (65 checks)。芯は **INR の判定と指標の
`valid` が食い違わないこと** — INR が要求を下回る帯域で T30 が valid に
なったら画面の説明が嘘になる。ノイズフロア −70/−45/−28 dBFS × 6 帯域で確認。
数値は `docs/opera-acoustics-validation.md` §13 に記載。

### H5 ビューア: 時間範囲の再生反映と動画設定の ffmpeg 配線 (2026-08-08)

H5 ビューアで「時間範囲の入力が再生に反映されない」「動画設定 (FPS/解像度/
コーデック) が ffmpeg 呼び出しに反映されない」という 2 つの `unwiredNote` を
解消した。どちらも「入力欄はあるが効かない」状態だった。

- 新規 `src/io/MovieExport` (純関数のみ) — `frameRangeForTimes()` と
  `buildFfmpegArgs()`。ffmpeg を起動せずに selftest から検証できるよう、
  GUI から切り離してある

  **絞り込み自体を無効化して理由を出す** (フレーム番号を時刻とみなすような
  推測はしない)
- 時間範囲は再生と**書き出しの両方**に効く (画面で見ている範囲と書き出しが
  ずれない)。動画化するときだけ PNG を 0 始まりの連番に振り直す
  (ffmpeg の `%05d` が 0 始まりのため)。PNG 連番として出すときは元のフレーム
  番号を残す
- 動画設定は ffmpeg へ渡る。解像度「元のまま」を既定にして拡大でぼかさない。
  片側だけ指定したときは `-2` でアスペクト比を保つ。**scale は crop より前**
  (順序が逆だと yuv420p 用の偶数化が壊れる)

  未実装として明示・無効化した

検証 (selftest +27 checks)。実装中に**境界の浮動小数点問題**を見つけて直した:
時刻列が `t[i] = i·Δt` と積まれていると `9·1e-9 > 9e-9` になり、利用者が
「フレームの時刻ちょうど」を境界に入れたときにそのフレームが外れる。
相対イプシロン 1e-9 (フレーム間隔よりはるかに小さく、丸め誤差よりはるかに
大きい) で比較するようにした。

### 形状タブ: メッシュの自動修復 (2026-08-08)

`GeometryTab`「ジオメトリ修復」の「▶ 自動修復実行」が未実装 (検出のみ) の
まま置かれていたのを実装した。検出側 (`io/MeshDiagnostics`) は既に実計算
だったので、対になる修復側を足した形。

- 新規 `src/io/MeshRepair` (Qt Widgets 非依存、決定的) — 3 つの修復:
  ① 頂点溶接 (位相を作る前提工程。常に行う)、② 縮退三角形の除去、

- **穴埋めは実装していない**。塞ぎ方が一意でなく形状を変えるので、黙って

- タブは修復後に配置・変換をかけ直して検査をやり直し、何をどれだけ直したか
  (溶接・除去・反転の数、外向き化した成分数、残った穴) を必ず出す

検証は selftest +41 checks。既存の `orientedCube` 群を再利用して、構成した
欠陥から期待値が決まる形にした:

- 健全な立方体 → 溶接 28 頂点のみ、表面積 6a² と bbox が不変
- 1 枚裏返した立方体 → 不一致辺 3 本が **0** になり水密のまま、三角形は減らない
- 全面内向きの立方体 → 検出には引っかからない (向きは「一致」している) が、
  符号付き体積で外向きへ反転される。反転が符号を**厳密に**変えること
  (`vol6(fixed) == -vol6(inward)`) と、大きさが 6a³ = 4.8e-5 に一致することを確認
- 縮退三角形 → 除去され、`dropDegenerate = false` では残る
- 穴あき → 塞がず境界エッジ 3 本を報告、三角形は増えない
- 決定性と冪等性 (直したものを直しても幾何が変わらない)

浮動小数点まわりで 2 点、**テスト側の期待値が誤っていた**ので直した:
頂点が float なので 6V の比較は相対 1e-6 が要る (絶対 1e-12 では実測差
3.2e-12 で落ちる)。また `ImportedMesh` は常に三角形スープ (頂点を共有しない
形式) なので、修復後に再度溶接しても「消えた頂点 28」は変わらない — これは
正常なので、冪等性は幾何の一致で判定するようにした。

### 形状タブ: 主軸の自動検出 (2026-08-08)

「配置・変換」の「主軸を自動検出」チェックが未実装のまま置かれていたのを
実装した。傾いた STL を取り込んだときに、手で回転角を探さずに軸へ揃えられる。

- 新規 `src/io/MeshAxes` (Qt Widgets 非依存、決定的) — **面積重み付き**の
  慣性主軸。頂点をそのまま使う PCA は頂点密度に引きずられる (細かく切った
  面が重く効く) ので採らず、三角形ごとの閉形式 2 次モーメント
  `∫_T (p−g)(p−g)ᵀ dA = (A/12) Σ (p_i − g)(p_i − g)ᵀ` を平行軸の定理で
  積む。固有値分解は対称 3×3 の Jacobi 法 (乱数・時刻を使わない)
- 軸は固有値の降順、符号は「絶対値最大の成分を正」で一意化し右手系へ。
  配置・変換が X→Y→Z の順に回すので、その形から Euler 角を抽出する
- **主軸が縮退している形 (立方体・球のように回しても同じ) では回転を入れず
  理由を出す**。一意に決まらないのに角度を入れると「検出できた」と誤解させる

検証は selftest +27 checks。角度そのものではなく **戻した結果の形** で判定
する (主軸には符号・入れ替えの自由度があり、利用者にとっての正しさは
「軸に整列するか」なので):

- 軸に沿った直方体 → 第 1 主軸が最長辺の X、角度は 0、モーメントは狭義単調減少
- 既知の角度 (単軸 3 種 + 3 軸複合) で傾けた 2a×a×a/2 の直方体 → 検出した
  角度で戻すと bbox の辺長が元の (a/2, a, 2a) に一致する (相対 1e-5)
- 立方体は縮退として報告される
- 面積 0 に近い微小三角形を 200 個足しても第 1 主軸が変わらない
  (面積重み付けが効いていること — 頂点 PCA なら寄ってしまう)
- 決定性と不正入力

### 形状タブ: ボクセル化の内外判定 (一般化巻き数) と区間まとめの配線 (2026-08-08)

ボクセル化のオプション群が「入力欄はあるが Voxelizer が読まない」状態
だったのを、実装できるものだけ実際に効かせた。

- `Voxelizer::windingNumber()` — 一般化巻き数 (Jacobson et al., ACM TOG
  32(4), 2013)。各三角形が張る符号付き立体角の和 / 4π で、閉じた面の内側で
  1、外側で 0。立体角は Van Oosterom & Strackee (1983) の閉形式
  `tan(Ω/2) = a·(b×c) / (|a||b||c| + (a·b)|c| + (a·c)|b| + (b·c)|a|)` を
  `atan2` で評価する
- `VoxelOptions{ inside, mergeRuns }` を追加。内外判定 (レイの偶奇 / 巻き数)
  と「連続セルをまとめる」が実際に効く。**既定はレイの偶奇** — UI は
  巻き数が既定になっていて実装 (レイ) と食い違っていたので実装側へ揃えた
- **巻き数は法線の向きが揃っていることが前提**。揃っていないと + と − が
  打ち消し合い、内側でも w ≈ 0 になって全セルが「外」になる。GUI は
  `MeshDiagnostics::inconsistentEdges > 0` なら実行せず、PR #66 で入れた
  「ジオメトリ修復」(法線統一) へ誘導する
- 表面処理の共形・サブセル、PVF、八分木、GPU はエンジン未実装なので
  個別に markNotImplemented を付けて、何が効いて何が効かないかを明示した

検証は selftest +45 checks。**穴の開いたメッシュでの差が採用理由そのもの**:

| 手法 | 占有セル (真値 216) | 誤差 |
|---|---|---|
| レイの偶奇 | 126 | 90 |
| 一般化巻き数 | **216** | **0** |

閉じたメッシュでは両者一致 (216 セル / 36 直方体)。巻き数は内側で |w| = 1、
外側で 0 が 1e-9 で成り立つこと、箱の大きさに依らないことも確認した。
「まとめない」設定は占有セル数を変えずに 1 セル 1 直方体 (216 個、各 1 セル幅)
になることを検証している。

実装中に、テスト用の `boxMesh` が **向きの揃っていない三角形スープ** だった
ことが分かった (レイの偶奇は向きに依らないので今まで露見しなかった)。
外向きで首尾一貫するよう直した — 巻き数の検証にはこれが必須。

### 形状タブ: ボクセル化の部分体積率 (PVF) を配線 (2026-08-08)

前項で「エンジン未実装」として残していた PVF を実装した。**セルを部分的に
埋める表現ではない** — `.ofd` の geometry は直方体単位なので、そもそも
半端に埋まったセルは書けない。PVF が置き換えるのは **占有判定** の方で、
セル中心 1 点の可否判定を N³ 点の体積率 f に置き換え、`f >= 0.5` を占有とする
(材質の内挿 = 共形/サブセル FDTD はカーネル側の機能なので引き続き未実装)。

- 面が横切るセル (境界セル) だけを再標本化する。三角形の AABB が重なる
  セルを立てるので **必ず超集合** になり、立たなかったセルには面が通らない
  = 中心 1 点で厳密に決まる。無駄な再標本化は境界の一層ぶんに限られる
- `VoxelOptions{ pvf, pvfSamples, pvfThreshold, pvfWorkCap }` を追加。
  **`pvfSamples = 1` は中心 1 点そのものなので従来と完全に一致する**
  (従来判定は N = 1 の特別な場合)。GUI は N = 4 (64 点) で呼ぶ
- `VoxelResult` に `stairVolume` (占有セルの総体積) / `pvfVolume` (Σf·セル体積)
  / `boundaryCells` を追加。ボクセル統計の「境界セル数」「形状誤差」が
  実測値になった (PVF 無効時は「— (PVF 無効)」のまま)
- 再標本化の作業量 (境界セル × 標本数 × 三角形数) が上限を超えたら
  **黙って粗くせずエラーにする**。何を計算したか分からない結果を出さない

検証は selftest +18 checks。立方体は閉形式と厳密に一致する:

格子 0.2 m、立方体 [−0.55, 0.55]³ (厳密体積 1.331 m³)、N = 8 の標本間隔
0.025 m → 軸方向の標本 44 点 = 長さ 1.100 ちょうど。よって

| 量 | 値 | メッシュ体積との差 |
|---|---|---|
| セル中心 1 点判定 | 216 セル = 1.728 m³ | **+29.8%** |
| PVF の体積推定 | 1.331 m³ | **±0 (厳密)** |
| PVF 閾値 0.5 の占有 | 208 セル = 1.664 m³ | +25.0% |

208 セルも閉形式で決まる: 軸ごとの占有率が [0,0,.75,1,1,1,1,.75,0,0] なので
1·1·1 → 4³ = 64、1·1·.75 → 3·32 = 96、1·.75·.75 → 3·16 = 48 の計 208
(.75³ = 0.422 の角 8 セルだけが閾値未満)。

曲面 (直径 5 セルしかない粗い格子の球) では、多面体の厳密体積に対して
階段近似が 13.1% ずれるのに対し PVF の体積推定は N = 2/4/8 で
0.92% / 0.24% / 0.05%。**対象は球ではなく多面体なので誤差は単調には
減らない** (面の位置と標本格子の噛み合わせで上下する) ため、判定は
単調性ではなく「N ≥ 4 で 1% 未満」にしてある。

### 光タブ: S パラメータの Touchstone / CSV 出力を配線 (2026-08-09)

光タブ「S パラメータ抽出」の出力ボタンが未配線だったのを解消した。同時に
`io/Touchstone` を**読み側込み**に拡張し、これまで書き出し 2 関数だけで
どこからも呼ばれていなかったモジュールに実利用者を与えた。

**判明した事実 — カーネルの `test.snp` は Touchstone 準拠ではない。**
`ofd` / `orcwa` の `sol/outputSpara.c` はポート 1 だけを励振して
S_n1 (行列の **第 1 列**) を計算するので、1 行あたりの数値は `1 + 2·N` 個
(準拠なら `1 + 2·N²`)。2 ポートなら 5 個で、Touchstone が要求する
S11 S21 S12 S22 のうち後半 2 つが存在しない。

そのため出力は次の 2 本立てにした (**欠けた要素を仮定で埋めない** —
相反性を仮定して S12 = S21 と置いても S22 は依然不明で、埋めた瞬間に
「計算していない値」を出力することになる。絶対規則 5):

- **CSV** — 選択した S11 / S21 について `|S|[dB]`、位相 [deg] (「位相情報を
  含む」時)、群遅延 [ps] (「群遅延」時)。カーネル出力でも第 1 列は実測値
  なので、入力ポート 1 なら S11・S_n1 とも完全に出せる
- **Touchstone** — 選んだポート対の**全要素が計算済みのときだけ** `.s1p` /
  `.s2p` を書く。書けない場合は理由 (S12/S22 が無い) を明示して CSV のみ
  出力する。入力ポートに 1 以外を指定した場合は「その励振は計算されて
  いない」と言って中断する

`Touchstone::read()` は Touchstone 1.x の周波数単位 (HZ/KHZ/MHZ/GHZ)・
数値形式 (MA/DB/RI)・基準抵抗 `R` を解釈し、**2 ポートだけ列順が
S11 S21 S12 S22 と転置になる仕様**を読み書きの両方で吸収する
(`TouchstoneData::s` は常に行優先)。第 1 列だけのファイルは
`column1Only` を立て、`isKnown()` / `series()` / `subset()` が
**未知要素を配らない**。1 行の数値が「N ポート全行列」とも
「M ポート第 1 列」とも読める場合 (9 個 = 2 ポート全行列 / 4 ポート第 1 列)
は 拡張子 `.sNp` → 呼び出し側のポート数 → 準拠解釈 の順で解く。
雑音パラメータブロック (周波数が戻る) は S データの終わりとして切る。
Touchstone 2.0 の `[Version]` 記法は誤読せずエラーにする。

検証は selftest +62 checks (8116 → 8178):

- 2 ポート全行列の往復と、書いたテキストの**列順が S11 S21 S12 S22**
  であることの直接確認
- カーネル形式 (`# Hz S MA R 50` + 第 1 列) の読み分け、
  `isKnown` / `series` / `subset` が未知要素を配らないこと
- DB/GHZ/R 75 の解釈 (−20 dB → |S| = 0.1、−40 dB∠−90° → −0.01j)
- N = 3 (複数行 1 レコード) の往復、`portsHint` による曖昧さの解消、
  雑音ブロックの切り落とし、Touchstone 2.0 の拒否
- 群遅延: 純遅延線 S21 = exp(−i·2πfτ) (τ = 5 ps) に対し位相の連続化が
  単調で 1 ステップが −2π·df·τ、群遅延が **τ に対して誤差 < 1e-15 s**
  (位相が線形なので中心差分は厳密)

### 電磁ポスト: スミスチャート / S11 表示と回路系タブの表記修正 (2026-08-09)

計算結果を確認する画面 (中央ペインの「プロット」) に **スミスチャート**
モードを追加した。素データは既存の周波数特性と同じ `<kernel>.log` の
給電点表なので、**カーネル側の変更も新しい実行も要らない** — 実行済みの
結果がそのまま反射平面で見られる。

新規 `src/em/Reflection` (Qt 非依存) が計算実体:

- `Γ = (Z − Z0)/(Z + Z0)`、`|S11|[dB] = 20 log10|Γ|`、
  `VSWR = (1+|Γ|)/(1−|Γ|)`、逆変換 `z = (1+Γ)/(1−Γ)`
- スミスチャートの目盛は円になる — 等抵抗円は中心 `(r/(1+r), 0)`・
  半径 `1/(1+r)`、等リアクタンス円は中心 `(1, 1/x)`・半径 `|1/x|`
  (Pozar, *Microwave Engineering* 4th ed. §2.3/§2.4)

**∞ を丸めない。** 完全整合の `S11[dB]` は −∞、全反射の VSWR は +∞ を
`std::numeric_limits<double>::infinity()` のまま返す。有限値へ丸めると
「整合していないのに整合して見える」ため (絶対規則 5)。表示側は
`std::isfinite()` で分岐して「−∞ (完全整合)」「∞ (全反射)」と出し、
CSV では該当列を**空欄**にする。

表示の内容:

- 単位円 (|Γ| = 1) と等抵抗円 r ∈ {0.2, 0.5, 1, 2, 5} / 等リアクタンス円
  x = ±{0.2, 0.5, 1, 2, 5} (単位円でクリップ)、実軸、中心の整合点
- Γ の周波数軌跡 (○ = f 最小、● = f 最大 で掃引の向きが分かる)
- 読み取り値: feed 番号・Z0・周波数範囲・**|Γ| が最小になる周波数**での
  Z / |Γ|∠θ / S11[dB] / VSWR
- CSV 出力は `feed, frequency_Hz, Rin, Xin, Z0, Γre, Γim, |Γ|, ∠Γ, S11_dB, VSWR`

**S21 は出さない。** `ofd` の給電点表は給電点ごとの Zin しか持たないので
1 給電点 = 1 ポート、つまり S11 = Γ しか定義できない。伝達項が無いことを
画面の注記で明示する (光ドメインの S パラメータ抽出とは別系統)。

**回路系電磁解析タブの表記修正 (実装済みの機能を未実装と書いていた)。**
`CircuitSolversTab` の「抽出実行」は OpenPEEC (`peec`) / OpenFEM (`ofe`) を
`QProcess` で起動して `zin.csv` / `ofe.log` を読み込む実装が既に入っている
のに、ポート表と結果ページの注記が「抽出エンジンの起動は未実装」「ポート
定義は計算に渡されません」と書いたままだった。実際の動作 (有効なポート行が
`.peec` の `port` / `.ofe` の端子として書き出される、結果は上の表に出る) に
合わせて書き換えた。絶対規則 5 は「未完成を動作済みと見せない」ことだが、
逆向きの誤記も利用者を機能から遠ざけるので同じく直す。

検証は selftest +63 checks (8178 → 8241):

- 整合 (Γ=0, VSWR=1, S11=−∞)・短絡 (Γ=−1, ∠180°, VSWR=∞)・開放 (Γ=+1)
- `Z = 2Z0` → Γ = 1/3・VSWR = 2・S11 = −9.542 dB (手計算)
- 複素負荷 `Z = 25 + j50` → Γ = 1/13 + j8/13、|Γ| = √(5/13)、逆変換で復元
- 受動負荷 (R ≥ 0) は必ず単位円の内側に入ること (20 通り)
- 目盛円: r=0 が単位円、r=1 が中心を通る、x=±1 が実軸対称、x=0 は円でない
- **目盛円上の点を逆変換すると本当に等 r / 等 x になること** (円の式の検算)

なることを確認した。

### EMC/EMI: FDTD 遠方界からの放射エミッション予測を配線 (2026-08-09)

`EmcTab` の放射エミッションは「限度値だけが実データで、被測定値・マージン・
判定は常に『—』」という状態だった。FDTD の遠方界 (far1d.log) を規格と同じ
土俵 (測定距離での電界強度 [dBμV/m]) に載せて、判定まで出せるようにした。

**鍵は far1d.log の値が何かを確定させたこと。** OpenFDTD の
`post/outputFar1d.c` が書く `E-abs[dB]` は `sol/farfield.c` の
`farfactor()` を掛けた場の 20log10 で、給電のある問題では

    ffctr = k / √(8π·η0·P_in),  P_in = Σ_feed 0.5·Re(V·I*)

である。利得の定義 `G = 4πr²|E|²/(2η0 P_in)` を書き下すと `G = ffctr²·|I|²`
となり、**出力値の 2 乗がそのまま利得**になる。つまり

    far1d.log の E-abs[dB] = 利得 [dBi]

**平面波入射 (`planewave`) では成り立たない** (farfactor が `k/(E_inc√4π)` に
なり RCS 系の量になる)。給電のある問題専用であることを画面に明示している。

新規 `src/em/RadiatedEmission` (Qt 非依存) が換算の実体:

    E[dBμV/m] = 134.771 + 10log10(P_t[W]) + G[dBi] − 20log10(d[m])
    134.771 = 20·log10(√30 × 10⁶)

**P_t は利用者が入れる。** `.ofd` の給電振幅は規格化された任意値なので、
実機の放射電力は GUI からは知り得ない。P_t が無い間は換算せず、その理由を
出す (絶対規則 5 — 校正なしの絶対値を出さない)。

画面 (放射エミッションの「FDTD 結果からの予測」節):

- far1d.log のパス (プロジェクトの隣を自動探索、参照ボタンあり)
- 放射電力 P_t [W]、放射体の最大寸法 D [m]、グランド反射 +6 dB の加算
- 周波数ごとに **切断面全体の最大利得** → 予測電界 → 規格限度 → マージン →
  予測判定。限度値表の範囲外の周波数は「範囲外」と言い、判定を出さない
- 予測値は下の判定結果の表 (区間内の最悪値) と限度値曲線にも重なる
- 遠方界条件 2D²/λ を測定距離が下回る周波数があれば警告を出す

適用限界も画面に列挙した: 給電のある問題専用 / far1d の切断面内の最大で
あって全球最大とは限らない / 自由空間の式 (実サイトは +6 dB) / 予測であって
実測ではない。

検証は selftest +51 checks (8241 → 8292、実カーネルあり):

- 定数項が 20log10(√30×10⁶)、1 W・0 dBi・1 m で 134.771 dBμV/m・30 dBm EIRP
- dB 経路と V/m 経路 (`√(30GP)/d`) が独立計算で一致すること
- 距離 3 倍で −9.542 dB、電力 4 倍で +6.02 dB、利得 +10 dBi で +10 dB
- グランド反射上限 = 20log10(2)、遠方界距離 = 2D²/λ、マージンの符号
- **CISPR 32 Class B の限度値を EIRP に逆算すると 1 μW 未満**であること、
  その EIRP を戻すと限度値に厳密に一致すること
- **実カーネル統合 (`OFDX_OFD_BIN`)**: `ofd` → `ofd_post` を回して far1d.log を
  作り、`dipole.ofd` (全長 50 mm = λ/2 @3 GHz) の最大利得が **2.15 dBi**
  (半波長ダイポールの教科書値) と ±0.3 dB で一致し、最大放射が素子に直交する
  θ=90° に出ることを確認する。**「E-abs[dB] は利得である」という前提そのものを
  教科書値で押さえる回帰**で、ここが崩れたら換算式ごと間違っている

### 形状取込: OBJ / PLY に対応 (StlImporter → MeshImporter) (2026-08-10)

### 回路系: SPICE ネットリストの取込 → .ofd の load 行 (2026-08-10)

「コンポーネントの取込みモデルでの回路設計図のファイルもここに追加？」への
対応。回路系電磁解析タブの「SPICE 連成」は**ファイル選択欄にパスを入れる

新規 `io/SpiceNetlist` が SPICE ネットリスト (.cir / .sp / .net) を読み、
R / L / C を取り出す。取り出した素子は **`.ofd` の `load` 行**
(`load = <dir> <x> <y> <z> <R|L|C> <value>`) としてプロジェクトへ入る。
`load` は本家 OpenFDTD の入力キーそのものなので、**取り込んだ素子は
カーネルまで届く** (GUI 内で完結しない)。

対応範囲と、あえて対応しないもの:

| 項目 | 扱い |
|---|---|
| 2 端子 R / L / C 行 | 取り込む |
| 先頭行 | タイトル (回路行として解釈しない) |
| コメント `*` / 行中 `;` | 除去 |
| 継続行 `+` | 直前の行へ連結 |

**読み飛ばしたものは必ず警告に残す。** 黙って落とすと「取り込んだつもりの

3 桁ずれるので selftest で名指しで固定した。接尾辞の後ろの文字は単位表記と
みなして読み捨てる (`4.7kOhm` = 4700)。

- 接尾辞の全種類。**`1m` = 1e-3 と `1meg` = 1e6 を別々に**確認
- `.subckt` の中の素子が**取り込まれないこと**、読み飛ばした `.subckt` と

黙っていたので「反映されない」ように見えていた。

新規 `core/PostPrereq` (Qt Core のみ) にこの前提を写し、ポスト(1) / ポスト(2)
の先頭に **出ない項目とその理由**を出すようにした:

```
⚠ チェックが入っていても、このプロジェクトでは出力されない項目が 8 件あります:
  給電点波形・スペクトル (給電点が無い)、… S パラメータ (観測点が無い)、
  結合係数 (給電点も観測点も無い)。
  給電点は「④ 波源」タブ、観測点は「⑤ モニター」タブ、
  frequency1 / frequency2 は「全般」タブで設定します。
```

**S パラメータだけ観測点で、結合係数は両方**という非対称性は取り違えやすい
(給電点だと思い込みやすい) ので、selftest で名指しで固定した。

検証は selftest +97 checks (8407 → 8504、実カーネルあり):

- 前提の表を全項目・全欠落パターンで検査。特に spara が観測点、coupling が
  両方であること、frequency1 は周波数特性だけ・frequency2 は遠方界近傍界だけを
  塞ぐこと
- `postInputsOf()` が frequency の点数を **div + 1** で数えること
  (OpenFDTD sol/input_data.c:420)、キーが無ければ 0 点
- **実カーネル統合**: `em_rcs` テンプレート (給電点・観測点なし) に 9 項目を
  チェックして `ofd` → `ofd_post` を回し、**ev.ev2 のページが実際に 1 枚だけ**
  であることを確認する。GUI の予告 (8 件が出ない) がカーネルの実挙動と
  一致することの検証で、ここがずれたら予告が嘘になる

なお調査の途中で `.ofd` の `end` 行より後ろに書いたキーは読まれないことを
実測で確認した (最初の実験はそれで空振りした)。

### 散乱/RCS: カーネルが出した散乱断面積を表示する (2026-08-10)

ポスト処理の見直しの続き。散乱/RCS タブは設定だけで**実行結果を何も出して
いなかった**が、カーネルは平面波入射の問題について `<kernel>.log` へ
散乱断面積を書いている:

```
=== cross section ===
  frequency[Hz] backward[m*m]  forward[m*m]
    3.00000e+09    1.2594e-02    1.9587e-01
```

`sol/outputChars.c:37` — `IPlanewave && NFreq2` のときだけ書かれる。
**単位は m² の実値**で、給電電力ではなく入射平面波で正規化されている
(`sol/farfield.c` の farfactor が平面波分岐を持つ) ので、そのまま dBsm へ
換算できる。

- `io/KernelResultReader` に `readCrossSection()` を追加 (見出しの次の節まで、
  数値行だけを読む)
- 新規 `em/RadarCrossSection` (Qt 非依存) — m² / dBsm / σ/λ² / σ/(πa²) と
  電気サイズ ka。**σ は電力次元なので dBsm は 10log10** (20log10 ではない)
- 散乱/RCS タブに結果表 (周波数 / 後方散乱 / 前方散乱 / ka)。既存の「単位」
  コンボがここに効くようになったので、未反映注記に「反映されるもの」を併記した

**ka の基準半径は最大半寸法**にした。外接球半径 (半対角) を使うと球でも
√3 倍に膨らんで ka がずれる (実際に一度そうなって 5.445 と出た。正しくは
3.144)。球ならこれが半径そのもので、球以外では代表寸法の目安である旨を
画面に書いてある。

検証は selftest +50 checks (8482)、実カーネルありで 8532:

- dBsm の往復と、**2 倍が +3.01 dB になること** (+6.02 なら 20log10 の誤り)
- σ/λ²・σ/(πa²)・ka の定義式、0 や負の入力で無限大を丸めないこと
- カーネルの出力書式そのままのテキストを読み、見出し行を飛ばして次の
  `===` で止まること。cross section の無いログでは空を返すこと
- **実カーネル統合**: 本家の検証サンプル `sphere_rcs.ofd` (ka = 3.0, a = 0.05 m)
  を走らせ、GUI のパーサが読んだ値を**完全導体球の Mie 厳密解**
  (後方 4.0901e-03 m² / 前方 8.4797e-02 m²) と比べる。許容は本家の
  `sphere_rcs_check.sh` と同じ 0.625〜1.6 倍。期待値の出所がコードから独立
  している点が重要で、単位や桁を取り違えていればこの窓を外れる

### 最適化タブ: 「掃引」手法を実際に実行できるようにした (2026-08-10)

最適化タブは 3 つの実行ボタンが全部無効で、最適化ループが 1 つも動かなかった。
**「掃引」だけは既存の `kernel/SweepRunner` で実行できる**ので (散乱・検証・
ばらつきの 3 タブが既に使っている実績のある機構)、そこを配線した。

足りなかったのは「どの点が良いか」を決める部分だけだったので、新規
`kernel/OptimizeFom` に切り出した:

| FoM | 向き | 出所 |
|---|---|---|
| 反射 Ref [dB] | 最小化 | 給電点表 |
| VSWR | 最小化 | 給電点表 |
| 遠方界の最大 E-abs [dB] | 最大化 | far1d.log |
| 前後比 F/B [dB] | 最大化 | far1d.log の 0° と 180° の差 |

**最大化 / 最小化の向きは `fomMaximizes()` に集約**し、最良点の選択は
`bestPointIndex()` だけが行う。向きを呼び出し側に書くと必ずどこかで逆になり、
**最悪の点を最良と呼ぶ**ので、そこは 1 箇所に閉じ込めた。

値が取れない点 (カーネルが失敗した / その量を出していない / VSWR < 1 の
壊れた行) は `valid = false` にして候補から外す。0 や NaN を混ぜない。

画面は「振る量」「評価量 (FoM)」「評価周波数」を選んで実行するだけ。範囲は
既存の変数表の最小 / 最大 / 分割をそのまま使う。実行中はボタンが「中止」に
変わり、進捗バーと結果表 (振った値 / 評価量 / 状態) が伸び、終了時に最良点を
出して該当行を選択する。

**振れる量は掃引エンジンが対応しているものに限る** (平面波の入射角 θ / φ、
メッシュ分割の倍率)。形状寸法を振るには `SweepRunner` 側の対応が要るので
選択肢に出していない。変数表の「変数名」列は実在の量に結び付いていないため、
未反映注記に残したまま「最小 / 最大 / 分割の列は使われる」と併記した。

検証は selftest +18 checks (8482 → 8500) と、実カーネルでの通し確認:

- FoM の向き (反射・VSWR は最小化 / 利得・前後比は最大化) を名指しで固定
- 周波数指定ありは最近傍点、指定なしは各点の最良値を採ること
- 失敗した点・データの無い点・VSWR < 1 の行が候補から外れること
- 最良点の選択が向きに従うこと、無効な点が「良い数字」でも勝たないこと、
  同値なら先に出た点を採る (順序で決まるので再現する) こと
- **通し確認**: dipole をメッシュ倍率 ×1.0 → ×1.4 の 2 点で掃引し、カーネルが
  2 回走って結果表が埋まり、最良点が **−14.483 dB (×1.0)** — 2 点のうち小さい
  方 — として選ばれることを確認した

### ソルバ領域タブ: Δt (CFL 係数) と自動シャットオフを .ofd へ配線 (2026-08-10)

ソルバ領域タブの「シミュレーション時間」節は、Δt もステップ数も**表示だけ**
していた。CFL 係数を 0.5 にしても計算は何も変わらない — 画面が推定値を出す
だけの節だった。

`.ofd` には対応するキーが最初からある:

| 画面 | .ofd キー | カーネル |
|---|---|---|
| Δt = CFL 係数 × Courant 限界 | `timestep = <秒>` | `sol/input_data.c:473` → `Dt` |
| シミュレーション時間 ÷ Δt | `solver` の第 1 引数 (反復回数) | `Solver.maxiter` |
| 自動シャットオフのレベル | `solver` の第 3 引数 (収束条件) | `Solver.converg` |

`Project::courantDt()` はカーネルの `sol/setup.c:setup_timestep()` と同式
(`1/√(Σ 1/d²)/c`) なので、CFL 係数 = 1 がちょうど安定限界になる。

**既定は「反映しない」** — 節に「この節の値を計算へ反映する」チェックを足し、
OFF のあいだは `GeneralOpts` に一切書かない。したがって既存プロジェクトの
出力バイト列は変わらない (絶対規則 2)。`timestep` が既に書かれている
ファイルを開いたときだけ ON 表示にし、CFL 係数を `dt / courantDt()` として
逆算して見せる (書いてあるのに OFF と見せると画面と `.ofd` が食い違う)。

CFL 欄は逆算した丸め文字列が入るので、**利用者が実際にその欄を編集したとき
だけ** Δt を作り直す。そうしないと他の欄をいじっただけで、読み込んだ
`timestep` が丸め値に化ける。

自動シャットオフ OFF は `converg = 0`。カーネルの判定は
`fsum < fmax * converg` (`sol/solve.c:471`) なので 0 は決して成立せず、
「打ち切らない」に正確に対応する。

検証は selftest +14 checks (8500 → 8514) と実カーネルでの通し確認:

- `courantDt()` が等方メッシュで `d/(c₀√3)`、非等方で `1/(c₀√(Σ1/d²))` に
  一致すること。細かいセルを入れると Δt が必ず短くなること (安定条件の向き)
- `dt = 0` (既定) では `timestep` 行が出ないこと = 出力バイト列不変
- `dt > 0` の往復と、`dt / courantDt()` で CFL 係数が戻ること
- `converg = 0` が往復すること
- **実カーネル統合**: dipole.ofd を実行し、カーネルが自分でログに書いた
  `Dt[sec]` と GUI の `courantDt()` が一致することを確認する。期待値の出所が
  GUI のコードから独立しているので、式を取り違えればここで落ちる
- **手動での通し確認**: dipole.ofd に `timestep = 4.6545e-12` (CFL 0.5) を
  挿入して実行すると、ログの `Dt[sec]` が自動値 9.3089e-12 からちょうど
  半分の 4.6545e-12 に変わった (`Tw/Dt` も 54.572 → 109.142 と倍)

#### 副次的に直した二重書き込みの穴

`GeneralOpts` を書くタブが 2 つになったので、**片方の変更をもう片方が
取り込んでいない**問題が表面化した (ソルバ領域タブの PML 層数で以前から
あった)。取り込まないと、古い値を握ったままの「全般」タブで 1 項目でも
いじった瞬間に `apply()` が全項目を古い値で上書きする。

両タブとも `Project::changed` で `refresh()` するようにし、
**自タブの入力欄にフォーカスがあるあいだは上書きしない**ガードを入れた
(CFL 欄は 1 打鍵ごとに書き込むので、書式化されると入力そのものができない)。

### 結果プロット「ポスト表」— ev2d / ev3d を使わないポスト表示 (2026-08-10)

要望「ev2d/ev3D を使用しないポスト表示の画面対応を追加」への対応。

既に far2d.log / near2d.log の 2 次元マップと far1d.log の放射パターンは
ev を介さず描いていたが、**ポスト(1) の主役である給電点・観測点の波形と
スペクトルは ev.ev2 の中にしか無かった**。つまりチェックを入れても、
ev2d ビューワか HTML を開かないと中身が見られなかった。

`ofd_post` は作図と**同じ内容をテキスト表にも書いている**:

| ファイル | 内容 | 出典 |
|---|---|---|
| `feed.log` | 給電点の時間波形 (V, I) とスペクトル | `post/plot2dFeed.c` |
| `point.log` | 観測点の時間波形 (E) とスペクトル | `post/plot2dPoint.c` |
| `far0d.log` | 指定方向の遠方界の周波数特性 | `post/outputFar0d.c` |
| `near1d.log` | 線上の近傍界分布 | `post/outputNear1d.c` |

4 つとも「見出し行 → 列見出し行 → 先頭が通し番号の数値行」という**同じ形**を
しているので、`KernelResultReader::readPostTables()` 1 本で全部読める。列の
意味はカーネルが決めたものなので、GUI は**列名をそのまま持ち回り、解釈を
足さない**。

結果プロットに「ポスト表」モードを足し、表の選択コンボ・対数 Y 軸・CSV 保存を
付けた。

#### 横軸の選び方 (先頭列固定では線上分布にならない)

`near1d.log` は X / Y / Z の 3 列を持ち、線に沿って動くのはそのうち 1 つ
だけである。先頭の数値列を横軸にすると X の一点に潰れて線分布にならないので、
**表の中で値が変化する最初の列**を横軸に採る。値が変わらなかった列は捨てずに
注記へ回す (断面位置の情報そのものなので)。

ただし**行が 1 本しかない表では退避しない** — 周波数 1 点の `far0d.log` は
全列が「一定」に見えるので、退避すると系列が 1 本も残らず表ごと消える。

#### 縦軸は列ごとに正規化する

同じ表に単位の違う列が並ぶ (V[V] と I[A]、E-abs[dB] と degree)。共通の縦軸に
押し込むと桁の小さい列が潰れて「出ていない」ように見えるので、**列ごとに
自分の最小最大へ正規化**して重ね、各列のレンジを凡例に数値で書く。

#### 表示の訂正

ポスト(1) の冒頭注記は「この設定では結果プロットは変わりません」と書いて
いたが、ポスト表モードができたので**もう正しくない**。注記とログ文言
(`log_noplotdata`) を実態に合わせて直した。動くものを「反映されない」と
書くのは、未完成を動作済みと見せるのと同じだけ害がある。

検証は selftest +21 checks と、実カーネルでの通し確認:

- `feed.log` の波形 / スペクトル 2 ブロックが分離でき、V と I が入れ替わらない
- `near1d.log` の横軸が Z になり、固定座標 X / Y が注記へ回ること
- 1 行だけの `far0d.log` が消えないこと
- 列名がデータ列より少ないとき生成名で埋めること
- 表の無いテキスト・空テキスト・1 列だけの表からは何も作らないこと
- **実カーネル統合**: dipole.ofd に `plotfeed` / `plotfar0d` / `plotnear1d` を
  足して `ofd` → `ofd_post` を走らせ、**実際に書かれた 3 ファイル**を
  パーサに通す。時刻が 0 から単調増加すること、スペクトルが frequency1
  (2〜3 GHz) に収まること、near1d の Z がメッシュ全長 (±0.075 m) にわたること

### ポスト表の大規模データ対応 (2026-08-10)

前節の「ポスト表」は **ファイル全体を `QString` に載せ、全行を折れ線で描いて
いた**。dipole (30×30×31 セル) でも `near2d.log` が 117 KB あるので、規模を
上げれば素直に破綻する。要望「大規模データの場合の対応」の第一歩として、
自分で作った経路を先に直した。

#### 読み込み: 1 行ずつ + 行数の上限

パーサを行単位の状態機械 (`PostTableParser`) に分け、`readPostTables()` は
`QTextStream` で 1 行ずつ食わせる。全体を文字列に載せない。

行数が `kMaxTableRows` (20 万) を超えたら「**半分に間引いてストライドを倍**」を
繰り返す。残る行は必ず 0, s, 2s, … の等間隔になるので、横軸の目盛が歪まない
(先頭だけ密になる、といったことが起きない)。元の行数は `PostTable::totalRows`
に残し、画面に「N 行を M 点へ間引いた」と出す — **黙って切り捨てない**。

実際の反復回数はこの上限より桁で小さいので通常は効かない。安全網である。

#### 描画: 間引きではなく最小/最大の包絡線

点数が横方向の画素数を超えたら、**1 画素ごとの最小と最大を縦線で描く**。
単純に間引くと振動波形の山谷が消えて「振幅が小さくなった」ように見える —
波形の見た目が嘘になる。包絡線なら山谷が正しく残り、描画量も画素数で頭打ちに
なる。

検証は selftest +14 checks (8535 → 8549):

- 上限超えの表で元の行数が残り、残った行が**等間隔**であること
- 間引いても x と y が同じ行のまま対応していること (v = 2t を確認)
- 上限以下の表が「間引いた」と誤検知されないこと
- **ファイル経路とテキスト経路が同じ結果になること** (実装が 2 本あるので、
  片方だけ直したときにここが落ちる)
- 存在しないファイルからは何も作らないこと

#### 2 次元マップ (far2d.log / near2d.log) も 1 行ずつ読む

同じ問題がポスト表示の本体側にもあった。`readFar2d()` / `readNear2d()` は
ファイル全体を `QString` に載せていた。**`QString` は UTF-16 なのでファイルの
約 2 倍**を追加で使う (`QByteArray` と合わせて実質 3 倍)。これらのログは
セル数 (または角度分解能) と周波数点数の積で増えるので、規模を上げれば効く。

パーサを `Far2dCollector` / `Near2dCollector` (行を 1 本ずつ食わせる) に分け、
テキストからでもファイルからでも同じ処理を通すようにした。常時メモリに載るの
は **1 周波数ぶんの格子だけ**になる。

selftest はファイル経路とテキスト経路が同じ `FieldMap` (行数・列数・値・軸名・
周波数) を返すことを比較する。実装が 2 本あるので、片方だけ直したときに落ちる。

#### 残りのカーネル出力リーダも 1 行ずつ読む (`readAll` を消した)

給電点表 (`<kernel>.log`)・遠方界パターン (`far1d.log`)・散乱断面積・熱解析の
診断行も、まだファイル全体を `QString` に載せていた。同じ形に揃えて、
**`io/KernelResultReader` から `readAll()` を消した** — これでこのリーダに
「ファイルを丸ごと載せる経路」は 1 本も残っていない。

| 読み取り | 常時メモリに載るもの |
|---|---|
| `readFeedSweeps` | 給電点 1 個ぶんの周波数表 |
| `readFar1d` | 1 面 × 1 周波数のパターン |
| `readFar2d` / `readNear2d` | 1 周波数ぶんの格子 |
| `readPostTables` | 1 ブロック (上限 20 万行、超過分は等間隔で間引き) |
| `readCrossSection` / `readThermal` | 数点の診断値 |

`parse*(QString)` は文字列を受ける API として残してある (テストと、既にテキスト
を持っている呼び出し側のため)。両者が同じ状態機械を通るので、意味は一致する。

selftest はテキスト経路とファイル経路が同じ結果を返すことを 6 種類すべてで
比較する。読み取りの実装が 2 本ある以上、片方だけ直したときに落ちる必要がある。

### チャネル解析: MIMO とビームフォーミングを実計算へ (2026-08-10)

電波伝搬・チャネル解析タブの「送受信」節は、AP 台数・MIMO 4×4・ビーム
フォーミング・受信点の種別がどれも表示だけだった。このうち **MIMO と
ビームフォーミングは GUI 層だけで確定した値が出せる**ので配線した。

`em/RadioPropagation` に 2 本追加 (どちらも公刊の式):

| 追加 | 式 | 出典 |
|---|---|---|
| `arrayGainDb(N)` | 10·log10(N) | Balanis, *Antenna Theory* 4th ed. §6.3 |
| `mimoCapacity(B, SNR, Nt, Nr)` | min(Nt,Nr)·B·log2(1+SNR/Nt) | Telatar (1999) / Foschini–Gans (1998) |

チャネル特性表に「アレイ利得 (ビームフォーミング)」「空間多重の容量上限
(MIMO)」の 2 行を足し、チェックの状態で 4×4 / 1×1 を切り替える。

**アレイ利得は受信電力に足していない。** EIRP は定義上すでに送信アンテナ
利得を含むので、利用者が入れた EIRP がアレイ込みなら二重計上になる。
「単一素子に対する増分であり、上の受信電力には加えていない」と注記に明記し、
値は別行として出すだけにした。

検証は selftest +10 checks:

- 素子数 2 倍が **+3.01 dB** (+6.02 なら 20log10 の誤り)
- 1×1 の MIMO 容量が Shannon 容量と厳密一致すること
- ストリーム数が min(Nt,Nr) で決まること (4×2 は 2 本)
- **高 SNR では 4×4 が SISO の 3 倍超**、逆に**低 SNR では 2 倍に届かない**
  (電力を Nt 本へ等分する損が多重利得を上回る)。向きを両側から固定する
- 帯域 0・アンテナ 0 で 0 を返すこと (計算しない)

#### カバレッジ図 (受信点 = 格子)

「受信点」のセグメント選択も表示だけだったので、「格子」を選んだときに
**カバレッジ図**を描くようにした。`em/RadioPropagation::coverageMap()` が
送信点を中心に置いた水平面へ受信点を並べ、2 波モデルで受信電力 [dBm] を
求める。描画は既存の `widgets/FieldHeatmap` を再利用 (新しい部品を作らない)。

図はアンテナ指向性も遮蔽物も含まないので**円対称**になる。見通し内の距離
依存を見るための図である旨を注記に明記した。経路・個別点は配置の入力が要る
ので未実装のままで、選ぶと理由を出す。

##### 「ピークは送信点にある」は間違いだった

最初のテストは「最大は中心」と書いて**落ちた**。ブレークポイント距離
d_bp = 4·ht·hr/λ ≈ 700 m に対して図の半幅は 200 m なので、格子はまるごと
2 波の干渉領域に入る。最大は干渉が強め合うリング上に来るのが正しい
(画面にも同心円の縞が出る)。図の見た目についての思い込みであって、
モデルの主張ではなかった。

テストは言える不変条件に置き換えた: 格子が干渉領域に入っていること、
中心が遠方の隅より強いこと、包絡線 (内側 1/4 の最大 > 外側 1/4 の最大) が
距離とともに落ちること。加えて**格子の各点が 2 波モデルの直接評価と一致する
こと**を全点で比較する — 図が別の式で描かれていれば落ちる。

### 散乱/RCS: 完全導体球の Mie 厳密解を並べて表示 (2026-08-10)

「その他散乱量」の Mie チェックは表示だけだった。**理論値はカーネルが要らない**
(閉じた級数で書ける) ので、GUI 層だけで計算して結果表に並べられる。

新規 `em/MieSphere` (Qt 非依存)。完全導体球の Mie 級数:

```
x = ka = 2πa/λ
a_n = j_n(x) / h_n(x)
b_n = (x·j_{n-1}(x) − n·j_n(x)) / (x·h_{n-1}(x) − n·h_n(x))
σ_b = (πa²/x²)·|Σ (−1)ⁿ (2n+1)(a_n − b_n)|²
σ_f = (πa²/x²)·|Σ     (2n+1)(a_n + b_n)|²
```

球ベッセル `j_n` は**下向き漸化 (Miller)**、`y_n` は上向き漸化。`j_n` を上向きで
作ると n > x の領域で丸め誤差に埋もれる。打ち切りは Wiscombe の
N = x + 4·x^(1/3) + 2 に余裕を足したもの。

散乱/RCS タブの結果表に「後方 (Mie 厳密解)」「前方 (Mie 厳密解)」の 2 列を足し、
**形状が球 (shape 2) のときだけ**計算する。球でない形へ球の厳密解を並べると
比較になっていない値を出すことになるので、そのときは列を隠して理由を出す。

#### 検証の出所は 2 つともコードの外

| 検証 | 出所 |
|---|---|
| Rayleigh 極限 σ_b/(πa²) → 9·x⁴ | 古典的な解析的漸近形 |
| ka = 3.0 / a = 0.05 m で後方 4.0901e-03 m² / 前方 8.4797e-02 m² | 本家 `data/sample/sphere_rcs_check.sh` |

**片方だけでは足りない**: Rayleigh 極限は n = 1 項でほぼ決まるので、高次項が
壊れていても通ってしまう。ka = 3 は 9 項ほど効くので級数全体を見る。実装は
両方に 1e-4 (相対) 以内で当たった。

実カーネル統合では、`sphere_rcs.ofd` の実行結果 (階段近似) と、GUI が画面に
並べる Mie 値が**同じ許容窓 (0.625〜1.6 倍)** に収まることまで確認する。

### EMC: グランド反射を試験配置から計算する (2026-08-10)

放射エミッション予測のグランド反射は **配置に依らない一律 +6.02 dB** だった。
これは「直接波と反射波が同相で合成されるときの上限」であって、実際の増分では
ない。距離・アンテナ高・周波数で決まり、**打ち消し側に振れることもある**。

`em/RadiatedEmission` に `groundEnhancement()` を追加し、試験配置の
サイト種別・測定距離・アンテナ高から 2 波の増分を求めるようにした
(`em/RadioPropagation` の自由空間損と 2 波損の差)。

| サイト | 扱い |
|---|---|
| OATS / 半電波暗室 | 2 波 (グランドプレーンあり) |
| 全電波暗室 | 反射なし — 増分 0 (`applies = false`) |
| 反射室 | 距離基準の換算に載らないので反射分を加えない |

前提は CISPR 16-1-4 / ANSI C63.4 に合わせた: EUT は卓上配置で高さ 0.8 m、
受信アンテナは 1〜4 m を走査して**最大値**を測定値とする。画面には
「指定アンテナ高での値」と「1〜4 m 走査の最大」を両方出す (規格の最大を
使いたければアンテナ高をその値に合わせてもらう)。反射係数は Γ = −1
(水平偏波の grazing 入射) を仮定する。

**以前は全電波暗室でもチェックすれば +6 dB が乗っていた** — 物理的に無い
反射を足していたので、これは誤りの修正でもある。

検証は selftest +7 checks:

- 反射の無いサイト (全電波暗室 / 反射室) で `applies = false`・増分 0
- 1〜4 m を 0.05 m 刻みで走査して、**どの高さでも 6.02 dB を超えないこと**
  (超えたら 2 波の合成が壊れている)
- 走査の最大が、その走査に含まれるどの点の値より小さくないこと
- **強め合う高さと打ち消す高さが両方あること** — 一律 +6 dB ならここで落ちる
- OATS と半電波暗室が同じ 2 波幾何になること
- 走査の最大が上限に肉薄すること (規格が最大を拾う前提と整合する)
- 距離・高さ・周波数が非正なら計算しないこと

### SAR: 送信電力から遠方界の入射量を出す (2026-08-10)

SAR タブの「曝露源」節は、機器の選択も送信電力もどこにも読まれていなかった。

棚卸しの見立ては「送信電力は SAR 正規化の係数にできる」だったが、**これは
できない** — カーネルは SAR 分布を出さないので、正規化する対象が無い。
代わりに**遠方界の入射量**なら送信電力から確定した値が出せる:

```
S = P_t·G / (4πd²)   [W/m²]      E_rms = √(S·Z0)
```

ICNIRP 2020 / IEEE C95.1-2019 / FCC の**参考レベルは S と E で与えられる**ので、
この値はそのまま `Metric::IncidentPowerDensity` と比べられる。アンテナ利得と
評価距離の入力欄を足し、算出値と各規格の参考レベルとの比を出す。

#### 規格ごとに適用周波数が違う

最初は ICNIRP だけを引いていたが、1950 MHz では**「参考レベルがありません」と
出た**。ICNIRP 2020 の入射電力密度は 2 GHz 以上、FCC の MPE は 1.5 GHz 以上で、
この周波数は FCC にだけ該当する。1 つだけ引いて「無い」と出すと、他の規格には
有ることを隠すことになる。収録した 3 規格すべてを引いて、該当したものを
出典つきで並べるようにした。

#### 近傍界では出さない

反応性近傍界の境界 λ/(2π) より内側では遠方界の式が成り立たない。1950 MHz なら
24.5 mm で、**携帯電話やウェアラブルの密着配置 (5 mm) はこの内側**に入る。
その場合は値を出さずに、SAR を場の分布から直接求める必要がある旨を表示する。

検証は selftest +11 checks:

- 30 dBm = 1 W / 0 dBm = 1 mW
- 1 W 等方 1 m で S = 1/(4π)、**利得 +3.01 dB で 2 倍・距離 2 倍で 1/4**
- 画面が出す S と E_rms が同じ平面波の関係で結ばれていること
- 24 dBm 等方 1 m ≈ 0.02 W/m² / 2.74 V/m (画面表示の裏取り)
- 境界が λ/(2π) であること、1950 MHz で約 24.5 mm、**5 mm 配置がその内側**
- 電力 0・距離 0・周波数 0 では計算しないこと

### 回路抽出 (PEEC): 抽出ページの設定を実際に .peec へ渡す (2026-08-11)

回路系電磁解析タブの「抽出設定」は、PEEC ページの入力欄がどれも**匿名ウィジェット
のまま捨てられていた**。一方 `Project::circuit()` (`CircuitOpts`) には対応する
フィールドが最初からあり、`io/CircuitIO` はそれを読んで `.peec` を書いていた。
つまり**受け皿は揃っていて、画面から書き込む線だけが無かった**。

| 画面 (PEEC ページ) | `CircuitOpts` | `.peec` |
|---|---|---|
| メッシュ分割 [mm] | `peecMesh_mm` | `bar` 行の分割数 |
| 部分容量 Cp | `peecCapacitance` | `capacitance = 1` |
| 抵抗 (表皮効果) | `peecSkinEffect` | `skineffect = 1` |
| 遅延 PEEC / 準静的 PEEC | `peecRetardation` | `retardation = 1` |
| 周波数範囲 [MHz] と分割数 | `fmin_Hz` / `fmax_Hz` / `fdiv` | `frequency = f0 f1 ndiv` |

**部分インダクタンス Lp のチェックだけは無効化した。** Lp は PEEC の手法その
ものなので常に計算され、切れる設定ではない。押せるが効かないチェックを残す方が
悪い (絶対規則 5)。遅延 PEEC と準静的 PEEC は同じ 1 個の設定の裏表なので排他に

#### 実カーネルで通した

selftest に `OFDX_PEEC_BIN` ゲートの統合検証を足した。GUI が作った `.peec` を
**本物の `peec` に食わせて解く**。「文字列に正しい行が入っている」だけでは、
ソルバが受け付けるかは分からない。

期待値は 2 つともコードの外にある:

- 直流抵抗の閉形式 R = 1/(σ·w·t) = 1/(5.8e7 × 1e-5) = **1.724138e-3 Ω**
- インダクタンスは OpenPEEC の検証サンプル `data/sample/bar_single.peec` の
  記載値 **L = 1.141093e-6 H**

実測は R が閉形式と 0.1% 以内、L が記載値と 1% 以内で一致した。

### 回路抽出 (FEM): 渦電流解析が 1 度も走っていなかった (2026-08-11)

PEEC ページに続いて FEM ページを配線したところ、**ソルバ選択そのものが
`.ofe` に届いていない**ことが分かった。「渦電流 FEM」を選んでも
`CircuitOpts::femAnalysis` は初期値の `"C L"` のままで、生成される `.ofe` は
準静的解析の入力だった。

さらに `analysis = F` が要求する 3 つのキーを `io/CircuitIO::femText` が
**どれも書いていなかった**。実カーネルで順に確かめると:

```
*** analysis F requires the tline key (2D eddy current)
*** analysis F requires the frequency key
*** analysis F requires conductorsigma for conductor 0
```

つまり仮に解析種別が届いていても、その `.ofe` は**解けない**。

| 追加したキー | 条件 | 理由 |
|---|---|---|
| `tline = <軸>` | C / L に加え **F でも** | 2 次元渦電流は線路軸を要求する |
| `frequency = <Hz>` | **F / A のとき** | `Freq > 0` が必須。C/L だけの解析では書かない (tanδ 項が入って結果が変わる) |
| `conductorsigma = <id> <σ>` | σ を読む解析 (R / F / A / E) | 導体の DC 直列抵抗に要る |

PEC には有限の σ が無いので、`conductorsigma` には銅 (5.8e7 S/m) を入れる
(σ = 0 はカーネルが弾く)。

画面側は、ソルバ選択 → `femAnalysis` (準静的 = `C L`、RLGC チェックで `C L R`、
渦電流 = `F`)、femw の周波数範囲 [GHz] → `fmin_Hz` を配線した。
**`.ofe` は掃引を持たない**ので、範囲の下端を単一の動作周波数として使う旨を
画面に明記している。

#### 実カーネルで通した

`OFDX_OFE_BIN` ゲートの統合検証を足した。断面 2 次元の 2 導体を作って渦電流を
解かせ、

- `requires the …` の欠落キーエラーが**出ないこと** (以前はここで止まった)
- ログに `Analysis = F` と `Frequency = 1.000000e+08` が出ること
- 報告される表皮深さが **δ = √(2/(ωμσ))** と 2% 以内で一致すること

を確認する。表皮深さの期待値はテスト側で独立に計算しており、カーネルの出力とは
別の出所になっている。

### 光ソルバのクロスバリデーション: 一括実行を動かす (2026-08-11)

光学ソルバ選択タブの「クロスバリデーション」節は、再実行チェック 4 つが
どこにも読まれず、「全ソルバ実行」ボタンは `markNotImplemented()` で無効だった。

チェックしたソルバを**上から順に 1 本ずつ**起動するようにした。ソルバごとに
`optical().solver` を差し替えた `.ofd` を専用ディレクトリ (`cross_run/fdtd`
など) へ書き、`Runner` が解決したバイナリを `QProcess` で起動する。直列に
回すのは、同じ作業ディレクトリの出力を取り合わせないため。

`Project` は `QObject` でコピーできないので、書き出しのあいだだけ solver を
差し替えて**必ず元に戻す**。`touch()` を呼ばないので他のビューは動かない。

結果表には ソルバ / 状態 / 生成ファイル / 作業先 を出す。カーネルが見つからない
ソルバは「起動できず」と理由を出して次へ進む (途中で止めない)。

#### 数値の突き合わせはしていない

各ソルバの出力量が違う (RCWA は回折効率、BPM は伝搬電力、FDTD は近傍界/遠方界)
ので、共通の観測量へ落とす作業が別に要る。**「実行した」と「一致を確かめた」を
混同させない**よう、注記に明記した。

#### 「選択がカーネル入力に届いているか」を固定した

回路タブの渦電流で「ソルバを選んでも入力が変わらない」不具合を踏んだばかり
なので、光の 4 ソルバについて同じ不変条件を selftest に足した:

- 4 つの選択がそれぞれ正しいカーネルに解決すること
  (FDTD / BPM は自分のカーネル、RCWA と FMM は orcwa)
- 4 つの選択がそれぞれのカーネルが読めるヘッダを書くこと
  (`OpenFDTD 4 2` / `OpenRCWA 4 2`)

クロスバリデーションはこの対応が正しいことに全面的に依存する — ここが崩れると
「別のソルバを走らせたつもりで同じものを走らせる」ことになる。

### アンテナ特性: 切断面から出せる指標を実計算する (2026-08-11)

アンテナ特性タブの「放射 / 偏波 / アレイ」チェックはどれも読まれていなかった。
このうち **far1d.log の 1 切断面だけで確定するもの**は GUI 層で計算できる。

新規 `em/PatternMetrics` (Qt 非依存):

| 指標 | 定義 |
|---|---|
| ピークとその方向 | 最大値と角度 |
| 3 dB 幅 (HPBW) | ピークから両側 −3 dB へ落ちる点の間隔 (線形内挿) |
| SLL | 主ビームの外で最も高いローブの、ピークからの差 |
| F/B | ピーク方向とその 180° 逆方向の差 |

タブに「パターン指標」表を足し、CSV レポートにも同じ値を書くようにした。

#### 出せないものは理由を出す

指向性・放射効率・アンテナ効率は**全球積分が要る** (far1d は切断面しか持たない
— far2d の出力が必要)。偏波成分・軸比・XPD は **far1d.log が E-abs しか
持たない**ため出せない。未反映注記にこの理由を併記した。

#### 主ビームの境界で 2 回間違えた

1. **テストパターンの取り違え**: 一様開口の sinc を θ の全周で作ると
   u = πL·sinθ が sinθ の関数なので **180° にも同じ主ビームが立つ**。
   「サイドローブ」を探すと 0 dB が返り、教科書値 −13.26 dB と合わなかった。
   後ろ半分を −60 dB の床にして 1 本の主ビームにした。
2. **実装のバグ**: 2 つのヌルがパターン全体を囲っている (ローブが 1 つしか
   ない) とき、「ヌルの外側」を歩くとピークへ戻ってしまい、サイドローブ =
   0 dB という嘘を出していた。**歩行中にピークへ戻ったらサイドローブ無し**と
   する判定を入れた。カージオイドのテストがこれを踏んで落ちた。

#### 検証の出所は教科書値

| 検証 | 出所 |
|---|---|
| 一様開口の第一サイドローブ = −13.26 dB | 開口分布が一様なときの古典的な値 |
| 一様開口の 3 dB 幅 = 0.886·λ/L | 同上 |
| 半波長ダイポールの HPBW = 78° | E 面 cos(π/2·cosθ)/sinθ の −3 dB 全幅 |

さらに**実カーネル出力**にも当てる: dipole.ofd の far1d.log (5° 刻み) から
HPBW を測る。

#### 実カーネルの 3 dB 幅は 78° ではなかった (CI で発覚)

最初に書いた「実測 HPBW が教科書の 78° と ±4° で一致する」判定は誤りで、
CI の linux ジョブが落ちた (実測は 71.79°)。原因は期待値の方にあった:

- dipole.ofd の線導体は幾何長 50 mm = 0.5004λ だが、**放射パターンは
  L ≈ 0.6λ の有限長ダイポール**のもの (ボクセル化された PEC 線と給電
  ギャップのぶん電気長が伸びている)。
- 有限長ダイポールの解析式 F(θ) = [cos(kL/2·cosθ) − cos(kL/2)]/sinθ に
  L = 0.6λ を入れると、切断面全体が **−20 dB より上で 0.076 dB** の差で
  一致する。3 dB 幅も 72.8° で実測 71.79° に近い。

そこで判定を「教科書値の丸写し」から「**解析式のどの長さに一致するか**」へ
変えた (同じ角度列で解析パターンを作り、同じ patternMetrics へ通して
3 dB 幅が 1.5° 以内・形が 0.3 dB 以内)。合成パターン側にも
L = 0.5λ → 78° / L = 0.6λ → 72.8° と、5° 刻みでも幅が 0.5° 以内で出ることを
足した。

### レンズ設計: 3 次収差 (ザイデル和) を実計算する (2026-08-11)

レンズエディタタブの Merit 表は収差オペランド (SPHA/COMA/ASTI/DIST) を
「実光線追跡が必要 — 未実装」として「—」にしていた。これは**間違った
あきらめ方**で、3 次収差は近軸の縁光線と主光線の 2 本だけで閉形式に決まる
(W. T. Welford, Aberrations of Optical Systems §8 / R. Kingslake, Lens
Design Fundamentals §10)。

新規 `optics/SeidelAberration` (Qt 非依存):

| 量 | 式 |
|---|---|
| S_I 球面収差 | −A²·y·Δ(u/n) |
| S_II コマ | −A·Ā·y·Δ(u/n) |
| S_III 非点 | −Ā²·y·Δ(u/n) |
| S_IV 像面湾曲 | −H²·c·Δ(1/n) |
| S_V 歪曲 | 下記 (教科書形は A が分母に来る) |

A = n(y·c+u) は縁光線の屈折不変量、Ā は主光線の同じ量、H はラグランジュ
不変量。主光線は「視野角で入る適当な 1 本 + 縁光線の定数倍」で絞り中心を
通るように作る (近軸追跡は線形なので厳密)。

レンズエディタタブに「3 次収差 (ザイデル)」表 (面ごとの寄与 + 総和 +
ペッツバール半径 + ラグランジュ不変量) を足し、Merit の 4 オペランドを
d 線の波長単位で埋めた。光学タブ側の面データは固定の設計例のままなので、
そちらには「実計算はレンズエディタタブにある」と誘導だけを置いた。

#### 教科書形の S_V は 0/0 になる — 分母を約分した

S_V = −(Ā/A)(S_III + S_IV) は **平行光が当たる平面**で A = 0、かつ
S_III = S_IV = 0 になり 0/0 になる。実際、平凸レンズを平面側から使うと
歪曲が 0.0037 (本来 0) と出ていた。屈折不変量の恒等式

    Δ(u/n) = A(1/n'² − 1/n²) − y·c·Δ(1/n),   H = Ā·y − A·ȳ

を代入すると A が約分でき、分母の無い等価形

    S_V = Ā[ Ā²·y·(1/n'² − 1/n²) + c·Δ(1/n)·(A·ȳ² − 2·Ā·y·ȳ) ]

になる。A ≠ 0 の面で両形が 8 桁一致することを確かめたうえで、こちらを採用した。

#### 判定はすべて解析的な恒等式

| 検証 | 出所 |
|---|---|
| ペッツバール半径 = −n·f | 単レンズの古典的な結果 |
| 絞り密着の薄レンズで S_III = H²·φ | 曲げ (bending) に依らない |
| 同 S_IV = H²·φ/n、S_V = 0 | 同上 |
| 曲げても S_III/S_IV は動かず S_I だけ動き、最小は内側 | 単レンズの best form |
| 平凸は凸面を平行光側へ向けた方が S_I が小さい | 教科書 (実測で約 4 分の 1) |
| 同心面 (絞りが曲率中心) で S_II = S_III = S_V = 0 | Ā = 0 になるため |
| 絞りを動かしても S_I と S_IV は不変 | ザイデルの絞り移動式 |
| S_III* = S_III + 2E·S_II + E²·S_I | 同上 (E は S_II の変化から逆算) |
| 屈折率が変わらないダミー平面は 1 ビットも変えない | Δ(u/n) = Δ(1/n) = 0 |

薄レンズの恒等式は厚み 0 が数値上作れないので 1e-6 mm で近似しており、
相対 1e-6 で判定する (厚みを 10 分の 1 にすると差も 10 分の 1 になることを
実測して 1 次であることを確認済み)。

### 音源: ラインアレイの指向性を実際に合成する (2026-08-11)

音源タブ「アレイ・ライン音源」ページは素子数・素子間隔・splay・ステアリング・
サブの配置と遅延を並べていたが、どれも読まれていなかった。**これらは外部
ソルバーを使わずに合成できる** — 素子位置と遅延が決まれば遠方界は和で書ける。

新規 `acoustics/core/ArrayDirectivity` (Qt 非依存 / C++14):

    p(θ) = Σ_k g_k · D(θ − φ_k) · exp(i·k₀·û(θ)·p_k) · exp(−i·ω·τ_k)

箱は 1 つ上の箱の面に沿って下へ積み、splay は相対角で累積する (EASE /
ArrayCalc と同じ流儀)。素子単体は箱の高さぶんの連続線音源 sinc(π·h·sinψ/λ)。

画面には評価周波数を選ぶ欄とビームパターン図、指標表 (最大方向 / 主ローブの
3 dB 幅 / −6 dB カバー範囲 / 主ローブ外の最大 / アレイ長 / グレーティング
ローブ出現周波数) を出し、評価周波数が出現周波数を超えていて「蜂巣構造防止」
に印が付いているときは警告を出す。サブアレイ側は遅延に見合う間隔 (= c·τ) で
前後比・前方最大周波数を出す。

#### 3 dB 幅を「カバー範囲」と呼んではいけない

J カーブ (splay 0…14°) を付けても **主ローブ自体は細いまま**で、1 kHz で
5.4° しかない。客席をカバーしているのは複数ローブの包絡なので、
−6 dB が及ぶ角度範囲 (同条件で −3.6°〜+64.0°) を併記した。片方だけ出すと
「J カーブにしたのにビームが広がらない」という誤読を生む。

#### 検証 (`ctest` の acoustics.array — 59 checks)

一様直線アレイの 3 dB 幅 0.886·λ/(N·d) (N=32 で 0.1 % 一致)、第一サイド
ローブ −13.26 dB、ステアリング角の再現 (±0.1°)、グレーティングローブ出現
周波数 c/(d(1+|sinθs|)) ちょうどで ±90° が 0 dB になること、カージオイドサブ
(逆相 + τ = d/c) の後方が全周波数で −100 dB 以下・前方が +6.02 dB になること。
詳細は `docs/opera-acoustics-validation.md` §15。

#### 渡らないものは渡らないと書く

このページの設定は .ofd / .ofdx に対応キーが無いのでソルバーへは渡らない。
未反映注記を「画面の合成はこの設定から GUI が実計算したもの。ソルバ入力への
対応キーは無い」と書き分けた。「Air absorption 補償」は距離に依存する量で
遠方界の相対パターンには効かないため、無効化して明示する。

### ポスト表: 時間波形を窓関数つきスペクトルで見る (2026-08-11)

ev2d / ev3d を使わないポスト表示 (feed.log / point.log / far0d.log /
near1d.log の直接描画) に、**時間波形を周波数領域で見る経路**を足した。
モニタータブの apodization (「開始時 / 終了時 / 両端」) はこれまでどこにも
読まれていなかったが、意味するところはまさに「記録の端の過渡を落としてから
DFT する」なので、ここで実際に効くようにした。

新規 `core/WaveformSpectrum` (Qt 非依存):

- 解析窓は `audio/AudioEditEngine` の窓関数ライブラリ (15 種)、FFT は音響コアの
  自前 radix-2 を使う — **どちらも既にあるので再実装しない**。
- apodization は Tukey (raised-cosine) テーパを指定した側にだけ掛ける。
  解析窓 (全長に掛かる) とは別物なので 2 段構えにしてある。
- 出力は片側スペクトルを最大 0 dB で正規化したもの。窓とゼロ詰めで振幅の
  意味が変わるので絶対値は出さない。
- コヒーレント利得 Σw/N と等価雑音帯域幅 N·Σw²/(Σw)² を返し、画面に出す。

結果プロットの「ポスト表」モードで x 列が時間の表を選ぶと「スペクトル」
チェックが出る。窓と apodization を選べ、apodization の選択は QSettings
`post/apodization` でモニタータブと共有する (.ofd に対応キーが無いので
プロジェクトには保存しない — セッション設定)。

#### 等間隔判定を 1e-6 にしていて実データが全て弾かれた

「時間列が等間隔でなければスペクトルを作らない」判定の許容幅を、最初は
相対 1e-6 にしていた。実際の feed.log を通すと **1 本も通らなかった**。
原因は ofd_post の time 列が 6 桁の指数表記であること — dt = 9.309e-12 s に
対して桁落ちが 1e-14 s あり、隣り合う差が **0.1 % (実測 9.5e-4)** 揺れる。

許容幅を 2 % に広げ、dt も端から端までの平均で取るようにした (先頭の 1 差分は
丸めの外れ値になりうる)。30 % ずれるような本当の非等間隔はこの幅でも落ちる。
selftest の実カーネル経路に「実測のばらつきは 1e-6 より大きく 2 % より小さい」
という判定を置いて、閾値を戻せないようにした。

#### 検証

合成信号 (fs = 1 MHz, 1024 点) で:

| 判定 | 出所 |
|---|---|
| ビン中心の正弦波は隣のビンへ漏れない (< −100 dB) | 矩形窓の DFT の性質 |
| コヒーレント利得 Rect 1.0 / Hann 0.5 / Hamming 0.54 / Blackman 0.42 | Harris 1978 表 1 |
| 等価雑音帯域幅 1.0 / 1.5 / 1.36 / 1.73 bin | 同上 |
| ビン間中央の正弦波で Hann は矩形より 20 dB 以上漏れが小さい | 窓の効能 |
| 端のテーパは掛けた側だけを 0 にし、中央と反対端は 1 のまま | Tukey の定義 |
| テーパ率 0 は無効化と厳密に一致 | 後方互換 |
| ゼロ詰めは df を 1/4 にするがピーク位置を動かさない | DFT の性質 |

実カーネル出力 (dipole.ofd の feed.log) でも、Hann の ENBW 1.5 / 利得 0.5 が
そのまま出ること、励振が 3 GHz を覆い 18 GHz では 15 dB 以上落ちていることを
確認する。

### レイアウト: GDS の多角形を FDTD の形状へ変換する (2026-08-11)

レイアウトタブの GDS 取込は、これまで**内容を要約するだけ**だった。
`Project` の形状モデルは本家 .ofd の形状コード (直方体・楕円体・円柱 …) で、
任意多角形を受ける型が無いためである。多角形を**軸平行な矩形の集合へ分解**
すれば直方体で表せるので、そこを実装した。

新規 `io/GdsGeometry`:

- 分解は水平スラブ法。頂点の y で区間に切り、各区間の中央 y で辺との交点を
  求め、偶奇規則で内部区間にする。上下で x 区間が一致するスラブは 1 つの
  矩形へ結合する (結合しないと縦に細切れの直方体が大量に出る)。
- レイヤーごとの z 範囲で押し出して `Geometry` (shape = 1) にする。

#### 面積は厳密に保存される (斜辺があっても)

頂点 y の間では多角形の幅が y の 1 次式なので、中点で測った幅の積分は厳密
になる (中点則は 1 次式に対して厳密)。したがって**三角形や台形でも面積は
一致する**。一致しないのは形だけで、斜辺は階段近似になる。そこは
`manhattan` フラグで呼び出し側へ渡し、画面に「%1 個の多角形に斜辺が
ありました — 形は階段近似です (面積は保存されます)」と出す。
シリコンフォトニクスのレイアウトは通常 Manhattan なので実用上は厳密。

#### 画面

レイヤー表に「z 下端 [µm]」「厚さ [µm]」「材料#」の 3 列を足し (編集可)、
「選択レイヤを形状へ変換」ボタンで押し出す。既存の形状には**追加**する
(置き換えない)。変換後は多角形数・直方体数・底面積を出し、外接範囲が
チップサイズを超えていれば警告する。

**既定の z 値は「一般的な SOI 光導波路の目安」であって特定 PDK の値ではない**
ことを画面に明記した。PDK 別の断面は公開値を持っていないので、勝手に
それらしい数字を入れて権威があるように見せない (絶対規則 5 の趣旨)。

#### 検証 (selftest — 42 checks)

| 判定 | 出所 |
|---|---|
| 長方形は 1 個のまま / L 字は 2 個 / U 字は 3 個 | 直交多角形の最小分割 |
| 生成した矩形は互いに重ならない | 重なると材料が二重に置かれる |
| 面積が厳密に保存される (L 字 3.0 / U 字 5.0) | 靴紐公式と一致 |
| 三角形 0.5・台形 6.0 も厳密 | 中点則が 1 次式に厳密なため |
| 斜辺があれば manhattan = false | 階段近似であることの明示 |
| 押し出し後の XY は多角形から、Z はレイヤーから | 変換の定義 |
| 厚さ 0 のレイヤーは何も作らない | 「変換しない」の意味 |
| GdsIO で書いて読み直しても矩形数・面積が変わらない | ファイル経路込みの往復 |

### 車内音響: 騒音源の寄与を合成する (2026-08-11)

車内音響タブの騒音源チェック (エンジン透過音・ロードノイズ・風切り音 …) は
どこにも読まれていなかった。**源ごとのレベルが分かれば合計と寄与は閉形式で
出る**ので、そこを実装した。

新規 `core/LevelSum` (Qt 非依存):

    合計     L  = 10·log10( Σ 10^(Lᵢ/10) )
    寄与率   pᵢ = 10^(Lᵢ/10) / Σ 10^(Lⱼ/10)
    除去効果 ΔLᵢ = −10·log10(1 − pᵢ)

タブには「騒音源の寄与 (エネルギー加算)」表 (源 / レベル [dB(A)] / 寄与率 /
消したときの低減) と要約行を足した。レベル列は編集でき、対象 (乗用車 / EV /
鉄道 / 航空機) を切り替えると源の並びが入れ替わる。チェックを外した源は
合成に入らない。

#### 「1 つ潰しても効かない」ことを言う

上位 2 つの差が 3 dB 未満のときは「差が小さいので 1 つだけ対策しても効果は
限定的です (最大でも N dB)」と付ける。寄与分析で一番よくある誤解が
「一番うるさい源を消せば静かになる」なので、数字が出た時点でそこを言う。

#### 前提と限界を書く

- レベルは**入力値**で、既定値は代表的な走行条件の目安にすぎない
  (実測値や部品メーカーの値に置き換えてもらう)。校正された測定値ではない。
- 源同士は**無相関**とみなしている。相関があると干渉で ±6 dB ずれる。
- 伝達経路 (車室への入り方) は扱わない — 構造音響連成が要るので未反映の
  ままとし、注記を「チェックの、伝達経路の扱い」に書き分けた。

#### 検証 (selftest — 36 checks)

| 判定 | 出所 |
|---|---|
| 等レベル n 個で +10·log10(n) (n = 1,2,4,10,100) | エネルギー加算の定義 |
| 10 dB 下の源は +0.414 dB しか上げず、消しても同じだけ | 10·log10(1.1) |
| 寄与率の総和が 1 | 定義 |
| 除去効果が −10·log10(1−p) と厳密一致 | 閉形式 |
| 合計は最大の源と「全部同レベル」の上限の間 | 挟み撃ち |
| 源が 1 つなら合計は自分自身で、消せば全部消える | 端の場合 |
| 負のレベルでも同じ / 空や非有限は valid = false | 壊れた入力 |
